## 🔍 課題1：ファイル名文字化け（scr_05）

### 現象
チャット出力に「① UI診断スコアカード」等のラベル無し、ファイル名部分が全て`%E3%82...`のURLエンコード文字列で表示。

### 実運用の状態
```
📊 01_UI%E8%A8%BA%E6%96%AD%E3%82%B9%E3%82%B3%E3%82%A2%E3%82%AB%E3%83%BC%E3%83%89_%E3%82%AB%E3%83%89%E3%82%B9%E3%83%88.pptx
📊 02_%E6%94%B9%E5%96%84%E6%8F%90%E6%A1%88%E3%83%AA%E3%82%B9%E3%83%88_%E3%82%AB%E3%83%89%E3%82%B9%E3%83%88.pptx
📊 03_%E3%83%93%E3%82%B8%E3%83%A5%E3%82%A2%E3%83%AB%E8%A8%BA%E6%96%AD%E3%83%9C%E3%83%BC%E3%83%89_%E3%82%AB%E3%83%89%E3%82%B9%E3%83%88.pptx
```

### 原因特定

#### 原因1（主因）：Instructions側の日本語ファイル名指定
`gpts-package/01_Instructions_WebDiagnosis.md` の line 6, 199, 237, 296, 303 で、以下の日本語ファイル名を採用：
- `01_UI診断スコアカード_{サービス名}.pptx`
- `02_改善提案リスト_{サービス名}.pptx`

Code Interpreter（サンドボックス）内では日本語ファイル名は保存可能だが、**ChatGPT側でユーザーへの配布URL化する際、日本語部分がパーセントエンコーディングされる**。表示はファイル名そのものに依存するため、エンコード済み文字列がそのまま出る。

#### 原因2（副因）：レポートタイトル未表示
実運用スクショでは「① UI診断スコアカード」等のラベルが全く表示されていない。Instructions側の想定出力形式（K.標準コード line 199）：
```
📊 01_UI診断スコアカード_{サービス名}.pptx  → [ダウンロード]
```
が守られておらず、GPT側の応答生成でラベルが省略されている。

#### 原因3（重要）：Instructionsが3ファイル構成に未対応
Instructions内のコード（line 290-306）は **2ファイル生成のみ**：
- `01_UI診断スコアカード` (prs1)
- `02_改善提案リスト` (prs2)

「③ ビジュアル診断ボード」の生成コードがない。しかし実運用では**3ファイルが生成されている**（scr_05で3ファイル確認）ため、GPTs側の暗黙処理（`03_pptx_builder.py` の追加関数呼び出し）に依存している状態。

### 対策提案

#### 対策A（推奨）：Instructions改修 - ファイル名を英数字化＋レポートタイトル明示化
```python
# 変更前
file1 = f'/mnt/data/01_UI診断スコアカード_{service_name}.pptx'

# 変更後
file1 = f'/mnt/data/01_UI_Scorecard_{service_name}.pptx'
```

- ファイル名を英数字化：文字化け完全解消
- ダウンロード時にユーザーが日本語ファイル名で保存したい場合は、応答本文で「日本語ファイル名で保存する場合は `01_UI診断スコアカード_カドスト.pptx` としてください」と案内

#### 対策B：レポートタイトル出力形式を強制指定
Instructionsに以下を追加：
```markdown
## 応答テンプレート（厳守）

診断完了時は、以下のテンプレート形式で応答する：

診断が完了しました。{サービス名}として診断しました。

**① UI診断スコアカード**
📊 [ダウンロード：01_UI_Scorecard_{service_name}.pptx]
現状の10項目診断とランクを1枚に集約したスコアレポート

**② 改善提案リスト**
📊 [ダウンロード：02_Proposals_{service_name}.pptx]
優先度付きの改善提案5件

**③ ビジュアル診断ボード**
📊 [ダウンロード：03_Visual_Board_{service_name}.pptx]
構造マップ・Before/After・ユーザー行動フロー
```

#### 対策C（必須）：Instructions内の3ファイル対応化
Instructions line 290-306 に **prs3（ビジュアル診断ボード）生成コード** を追加：
```python
# 5. C-3（ビジュアル診断ボード）3スライドを生成
prs3 = create_presentation()
add_visual_diagnosis_board(prs3, visual_data, page_num=1, total=3)
# ...他2枚
file3 = f'/mnt/data/03_Visual_Board_{service_name}.pptx'
prs3.save(file3)
```
※実装関数名は`03_pptx_builder.py`の実装に合わせて確認・調整

## 🔍 課題2：C-3総評文字数切れ（scr_06）

### 現象
【3】ビジュアル診断ボードのスライド1「▼ 総評」枠内で、
> 「目的別導線と購入理由を整理し、迷わ…」

で切れている。「迷わず商品一覧へ進める」的な想定文が最後まで表示されない。

### 原因特定

#### 原因1（真因）：Instructions側のsummary文言が長すぎる
`gpts-package/01_Instructions_WebDiagnosis.md` line 289 のサンプル：
```python
'summary': '最優先の一手：ファーストビューに無料体験CTAを追加し、直下に成果・安心材料を3点で提示する。',
```
これは**全角換算34字**。C-3の総評帯は Meiryo 14pt / 352px 環境で**全角17文字が1行収容の実測限界値**（v14で確定）のため、機械的に17字で切られる。

#### 原因2（副因）：Instructionsに「17字上限」の指示が明記されていない
Instructions内で `summary` の文字数制約が言及されていない。GPTs実運用時に、AIは自然な長文を生成してしまい、PPTX側の `_truncate_full(17)` で機械的に切断される。

#### 実装側の状態（変更不要）
`gpts-package/03_pptx_builder.py` line 2983 で以下が実装済み：
```python
summary_text = _truncate_full(visual_data.get('summary', ''), 17)
```
line 2949-2953 のコメントに実測境界値が記載済み：
```
# 全角 17字（換算17.0）→ 1行内収容 ✅ 限界値
# 全角 18字（換算18.0）→ 2行折返し ❌
```

PPTX側の17字上限設計は正しく、**Instructions側で17字以内に自然な形で完結させる指示が不足**しているのが真因。

### 対策提案

#### 対策A（推奨）：Instructions側にsummary文字数制約を明記＋サンプル修正

`gpts-package/01_Instructions_WebDiagnosis.md` に以下を追加：
```markdown
## visual_data の生成ルール（厳守）

### summary（総評帯・1行完結）
- **全角17文字以内**で1行完結させる
- スライド1中央の総評帯に表示され、17字を超えると機械的に切断される
- 「〇〇〇して、〇〇〇へ進める」の形式で、動作×結果を含む短文にする
- 悪い例（34字）: 最優先の一手：ファーストビューに無料体験CTAを追加し、直下に成果・安心材料を3点で提示する。
- 良い例（17字）: FV内CTA追加で無料体験へ誘導
- 良い例（16字）: 目的別導線を整え離脱を防ぐ
```

サンプルコード（line 289）も17字以内に修正：
```python
# 変更前（34字）
'summary': '最優先の一手：ファーストビューに無料体験CTAを追加し、直下に成果・安心材料を3点で提示する。',

# 変更後（17字以内）
'summary': 'FV内CTA追加で無料体験へ誘導',  # 15字
```

#### 対策B（代替案）：PPTX側で自動改行対応（採用非推奨）
17字を超えた場合に自動改行させる実装案もあるが、v15で「1行運用」を確定させた設計思想を覆すため非推奨。
