### J-7. 図解パターン（ユーザー明示要求時のみ・v3.5_20260831 新設）

図解パターンは**ユーザーが明示的に要求した場合のみ**生成する（J-4 統合版と同じ位置づけ）。
既定の3ステップ対話フロー（I項）は一切変更しない。明示要求がない限り、従来どおり C-1/C-2/C-3 の3ファイルのみを納品する。

#### J-7-1. トリガー語句（これらが含まれる場合のみ生成）

- **図解の直接要求**：「図解で」「図解して」「図で」「図にして」「ダイアグラムで」「diagramで」
- **視覚化の要求**：「視覚化して」「ビジュアル化して」「チャートで」「図表で」

#### J-7-3. 標準コード（図解1枚を追加出力）

```python
# パターンキーは診断カテゴリから決定（DIAGNOSIS_TO_PATTERN 準拠）
pattern_key = DIAGNOSIS_TO_PATTERN.get(diagnosis_key, 'category')

prs_dg = create_presentation()
slide, report = add_diagram_slide(
    prs_dg, pattern_key, palette, diagram_data,

```

`palette` は `get_theme_palette` の戻り値を使う。ファイル名は J-1（英数字化）に従う。

#### J-7-5. 説明文（`description`）の推奨字数

**推奨上限：全角30字以内（目安）。**

図解パターンのカードは、要素数や段位置に応じて幅が動的に変わる。カード幅が一定以下（**目安：600px以下**）になる段では、説明文が2行に折り返した際に下辺との余裕が極小となる。

| 条件 | 下辺余裕（実測｜実座標 1280×720） |
|---|:---:|
| 説明文1行（全段） | 約 22px |
| 説明文2行（幅600px以下の段） | **1.4〜1.8px** |

**枠外への溢れは発生しない**（2026-09-08 実機画素実測により確認済）。実装は仕様どおり機能しており、本項は不具合の回避策ではなく**可読性を安定させるための運用ガイド**である。

**対象は特定のパターンに限らない。** `description` を持つ全パターン（`category` / `pyramid` / `sequence` / `funnel` / `cycle` / `timeline`）に共通して適用する。とりわけカード幅が段ごとに縮小する `funnel`（幅係数 0.90 → 0.40）と、要素数が上限に達したときの `pyramid`（n=5）で余裕が小さくなる。

**30字以内に収めた場合、説明文は概ね1行に収まり、下辺余裕 約22px が確保される。**

**30字は目安であり、上限ではない。** 実際に何行になるかは、段の幅とフォントで決まる（builder は描画前に文字幅推定で判定する｜J-7-6）。説明文が2行に折り返すことは設計上許容しており、枠外への溢れは発生しない（上記のとおり）。

**`funnel` の要素数6に限り、builder が縦の配分を自動で詰める（v17.2.14 r1〜｜2026-10-04 統括判定）。** 適用の条件は「要素数6」かつ「説明文が2行に折り返す段が1つ以上ある」ことの両方である。このとき段間を 10→5px、説明文の開始位置を段上端+34→+32px とし、段の高さは 76→80px となる。**この自動調整は `funnel` の要素数6だけに働く。** `funnel` の要素数3〜5、および他のパターン（`category` / `pyramid` / `sequence` / `cycle` / `timeline`）には自動調整はなく、上表の下辺余裕がそのまま当てはまる。

30字を超える必要がある場合は、次のいずれかで対応する。

1. 要素数を減らして1要素あたりのカード幅を広げる
2. 説明文を `label` 側へ分割する
3. 図解ではなく通常のスライド（C-2 提案書）で表現する

#### J-7-6. 文字揃えの適用基準

**説明文（`description`）は、2行以上に折り返す場合は左端揃え、1行に収まる場合は中央揃え。見出し・ラベル・記号は常に中央揃え。**

説明文が2行以上に折り返した場合、中央揃えでは行ごとに左端の位置が変動し、読者の視線の戻り先（次行の開始位置）が定まらない。

一方、説明文が1行に収まる場合は左端揃えの効用が働かない。むしろ中央配置の見出しに対して説明文だけが左に寄り、右側に大きな余白が生まれて視覚的に非対称となる（2026-09-16 実機確認で検出）。したがって**行数によって揃えを切り替える**。

判定は描画前に文字幅推定で行う。**折返しの判定には安全係数（`_V17_W14_SAFE`）を適用しない。** 安全係数は「枠を広く確保する」ための安全側バイアスであり、判定に用いると1行に収まる文字列を2行と誤判定するため（2026-09-17 実機24点で検証：安全係数あり22/24 → 素の推定幅24/24）。

| 要素 | 揃え | 理由 |
|---|:---:|---|
| 本文（`description`）｜**2行以上** | **左端** | 複数行時に左端が揃い視線の戻り先が一定になる |
| 本文（`description`）｜**1行のみ** | **中央** | 1行では左端揃えの効用（視線の戻り先の一定化）が働かず、中央配置の見出しに対して右側余白が目立ち視覚的に非対称となるため |
| 見出し（`label`） | 中央 | 1行で段差が起きない／本文との階層の区別にも寄与する |
| 軸ラベル・矢印・序列番号 | 中央 | 中央に置くこと自体が図解上の意味を持つ |

**適用条件（2026-09-19 統括判定 諮問① 案α）**：本基準のうち**「1行のみ＝中央」は、当該パターンの見出し（`label`）が中央揃えである場合にのみ適用する。** 見出しが左揃えのパターンでは本文も左揃えを維持する（行数で切り替えない）。

理由：「1行＝中央」の根拠は「中央配置の見出しに対して本文だけが左に寄ると右側余白が目立ち非対称になる」ことである（2026-09-16 判定）。すなわち本基準は**見出しが中央揃えであることを前提とする規準**であり、見出しが左揃えのパターンに機械的に適用すると「見出し左＋本文中央」という同種の非対称を逆向きに生じさせる。

| パターン | 見出し（`label`） | 本基準の適用 |
|---|:---:|:---:|
| `funnel`・`pyramid` | **中央** | **適用する（行数分岐）** |
| `category`・`breakdown`・`comparison`・`sequence`・`framework`・`cycle`・`contrast`・`timeline`・`network` 他 | 左端（既定） | 適用しない（**本文も左端を維持**） |

**適用済みのパターン**：`funnel`（2026-09-15 左端化／2026-09-17 行数分岐）／`pyramid`（2026-09-16 左端化／2026-09-17 行数分岐）。**2026-09-19 時点で本基準の適用対象は上記2パターンで完結している（対象2パターンで完了）。**

`framework` の軸ラベル（「低 ← 軸 → 高」）および矢印（「↑」「↓」）、`cycle` の円環名、`timeline` の軸ラベルは、いずれも1行または1文字であり中央揃えを維持する。左端揃えに変更すると軸の中心を示す意味が損なわれる。

#### J-7-7. フォールバック挙動（例外は投げない）

要素数がパターンの上下限を外れた場合、`category` へ自動フォールバックして描画を継続する。
生成が失敗して納品物が欠けることはない。フォールバックが発生した場合はその旨を一言添えて納品する。

#### J-7-9. `funnel` の任意キー `cumulative`

**`funnel` 専用のキーである。他のパターンに渡しても描画しない。** 指定しない場合、出力は変わらない。

スライド内タイトル行（y 90〜124）の右端に、最上段から最下段までの通算指標を1行・右揃えで描画する。段（body_top 138 以降）の座標には触れない。

| 値 | 挙動 |
|---|---|
| `None`・未指定 | 描画しない |
| `'auto'` | 自動算出する。**成立条件：全段に `value` があり、すべて0以上で、先頭段の `value` が0より大きく、段が2つ以上あること。** 不成立なら描画せず、理由を notes に記録する |
| 文字列 | その文字列を表示する（先頭に「→ 」を付す） |

**`'auto'` の表記**：「→ 通算 X%（先頭値→最終値＋単位）」。X ＝ 最終段 `value` ÷ 先頭段 `value` × 100。X < 10 のとき小数第1位まで、X ≧ 10 のとき整数で表記する。丸めは四捨五入（ROUND_HALF_UP｜例：10.5 → 11、1.65 → 1.7）。先頭値・最終値は桁区切りで表記する。

**衝突時は描画しない。** タイトルの推定右端＋24px が通算表記の左端を超える場合は描画せず、notes に「省略（タイトルと衝突）」を記録する。退避先は設けない。タイトルの推定右端は、描画前の文字幅推定（J-7-6）で求める。

#### J-7-10. `funnel` の任意キー `footnote`

**`funnel` 専用のキーである。他のパターンに渡しても描画しない。** 指定しない場合、出力は変わらない。

最下段カードの左の空き（x 40〜358｜最下段は要素数によらず x 400・幅480px のため領域は固定）に、最下段上端＋28px を起点として、14pt・標準ウェイト・本文色・左揃えで描画する。段の座標には触れない。

| 値 | 挙動 |
|---|---|
| `None`・空文字・空白のみ | 描画しない |
| 文字列 | 先頭が「※」でなければ「※」を付して描画する |

**収容を超える場合は描画しない。** 収容行数は「縦の空き（最下段の高さ − 28px）÷ 行高 22.4px（14pt × 1.2）」の切り捨てとする。必要行数が収容行数を超える場合は描画せず、notes に記録する。退避先は設けない。必要行数の見積もりには14pt太字用の推定器を用いるため、実際より行数を多めに見る（安全側の見積もり）。

注記を body_bottom（646）より下に置かないのは、フッター境界（660）までが14pxしかなく、14pt の1行が入らないためである。
