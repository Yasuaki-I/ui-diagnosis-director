## 4章｜「診断結果」を、"見せるための形" にまで仕上げる意味

### 4.0 この章で語ること（購入者への導入）

前章で、私はこう書きました。「診断結果は、そのまま提案書の叩き台になる」と。でも、あなたはたぶん、こう思ったはずです。

「叩き台になる、と言われても……実際に開いたとき、"それっぽく" 見えなかったら、結局作り直しでしょう？」

その懸念、まったくその通りです。**PPTXで出力されるだけでは、まだ道半ば** なのです。

診断結果を「そのまま提案書の叩き台」にするには、開いた瞬間に「これは、このまま出せる」と感じてもらう必要があります。そのために私は、**7つのテーマ×12種の図解パターン＝84通りの組み合わせマトリクス** を、設計哲学として組み上げました。

この章では、その84通りの背後にある「なぜこの色なのか」「なぜこの図解なのか」を、あなたと一緒に見ていきます。

---

### 4.1 7テーマは、"綺麗さ" ではなく "心理的整合性" で選ばれている

まず、7つのテーマの選定基準についてです。

私は、「見た目が綺麗だから」という理由で色を選んでいません。**プロジェクトタイプごとの心理的整合性** を根拠に、7つのテーマを設計しています。

| テーマ | 心理的トーン | 適合プロジェクトタイプ |
|-------|-----------|------------------|
| SolidGray | 中立・客観 | 全タイプ共通（事実提示） |
| Blue | 信頼・企業的 | コーポレート／BtoB |
| Cyan | 技術・革新 | Webアプリ／技術系 |
| Green | 成長・自然 | メディア／ブログ |
| Orange | 活力・行動 | LP／EC |
| Red | 警告・強調 | 全タイプ（限定発火） |
| LightBlue | 清涼・IT感 | Webアプリ／SaaS |

たとえば、BtoBのコーポレートサイトの診断で「Orange」を選んだら、意思決定者は違和感を覚えます。「なぜCTAの色を、うちの企業サイトの提案書に使っているんだ？」と。

逆に、ECサイトの診断で「Blue」だけを使うと、購買促進の温度感が伝わりません。**色は、プロジェクトタイプが持つ "文脈" に合致していなければ、機能しないのです。**

だから私は、テーマを7つに絞りました。7つあれば、想定される診断カテゴリのほぼすべてに「心理的整合性」を担保できます。8つ以上にしなかったのは、選定判断の曖昧さを排除するためです。

---

### 4.2 8色階調は、"色バリエーション" ではなく "視覚役割の分業"

次に、各テーマ内の色階調についてです。

7テーマそれぞれは、**8つの色階調（primary / secondary / midtone / light / lightest / accent / warning / bg）** で構成されています。

ここで大事なのは、これは単なる「色のバリエーション」ではないという点です。**8色階調は、視覚役割の分業構造** なのです。

- **primary**（最濃）｜メインタイトル・最重要データの強調
- **secondary**｜サブタイトル・第2層の情報
- **midtone**｜中間データ・区切り線
- **light**｜補助データ・背景要素
- **lightest**（最薄）｜視覚ノイズを最小化する最軽度データ
- **accent**｜特定要素の強調（例：矢印）
- **warning**｜警告色（スコア40未満時に発火）
- **bg**｜全体の基底層／他色を支える余白

つまり、「8色ある」のではなく、**「情報の重要度に応じて、どの色を割り当てるかが自動的に決まる」** のです。

これは、あなたが提案書を作るときに毎回悩んでいた「この見出しは何色にしよう」「この本文はグレーにするか黒にするか」という判断を、**設計側で先に済ませてある** ということです。

### 4.3 【本章の中核】12種の図解パターンは、"診断カテゴリと1対1対応" している

ここが、本章で **あなたに一番覚えて帰ってほしいポイント** です。

私は、12種の図解パターンを **診断カテゴリと1対1で対応させて** います。

| 診断カテゴリ | 対応パターン | 選定論理 |
|-------------|-------------|---------|
| proposal_categorization | category | 提案項目を並列カテゴリで整理する用途と、並列grid構造が一致 |
| priority_ranking | pyramid | 優先順位は上下階層で表現するのが視覚認知上最も強い |
| before_after | comparison | 改善前後の2要素対比はside_by_sideが最短経路 |
| user_flow | sequence | ユーザーフローは時系列ステップであり、arrow_chainが最適 |
| improvement_cycle | cycle | 継続改善サイクル（PDCA等）はcircle_arrowで反復性を強調 |
| conversion_funnel | funnel | コンバージョンファネルは絞り込み構造そのもの／trapezoidと1:1対応 |
| schedule | timeline | スケジュールは期間マイルストーン表現 → horizontal_bar |
| score_breakdown | breakdown | 10項目スコアの内訳表示はtree構造が階層明示に有効 |
| ux_contrast | contrast | UX上の対照的要素はsplit_screenで強調 |
| impact_cost_matrix | framework | インパクト×コストの2軸評価はquadrant（4象限）が定番 |
| site_structure | network | サイト構造はノード間関係であり、node_edgeで表現 |

なぜ1対1対応にしたのか。理由は3つあります。

**① 選定の透明性**：診断カテゴリが確定した瞬間に、使用パターンが自動的に確定します。「どのパターンを使おうか」と迷う時間がゼロになります。

**② 検証可能性**：どの診断カテゴリでどのパターンを使ったか、後から必ず追跡できます。あなたが「この図解、なんでこうしたんだっけ？」と迷うことがなくなります。

**③ 設計の持続性**：新しい診断カテゴリが増えても、対応パターンを追記するだけで拡張できます。将来の運用まで見据えた設計になっています。

**この1対1対応が、「提案書を、そのまま出せる叩き台にする」ための、核心の仕組みです。**

### 4.4 7×12＝84通りの組み合わせは、"迷わずに出せる" ための設計

7テーマ×12パターン＝84通り。この数字を見ると、「多い」と感じるかもしれません。

でも、あなたが実際にPPTXを開くとき、**選ぶ必要はありません。**

プロジェクトタイプが「コーポレート」で、診断カテゴリが「priority_ranking」なら、テーマは「Blue」、パターンは「pyramid」に **自動的に確定** します。あなたが選ぶのではなく、**設計側が事前に選定を済ませてある** のです。

各組み合わせに対して、以下のパラメータも自動決定されます：

- **font_size_title**：タイトルフォントサイズ
- **font_size_body**：本文フォントサイズ
- **grid_columns**：グリッド段数
- **element_max_count**：要素数上限（Miller's Law 7±2遵守）
- **contrast_ratio**：WCAG AAコントラスト比（アクセシビリティ）

つまり、84通りの組み合わせは「あなたが選ぶ余地」ではなく、**「あなたが迷わずに出せる」ための、事前選定リスト** なのです。

### 4.5 私は、この設計哲学の「実装体現度」を、こう測定しています

前章で「削減できるはず、ではなく、削減できる」を数字で証明する運用を続ける、と書きました。本章の設計哲学についても、同じ姿勢で検証しています。

**測定指標｜4項目**：

1. **色選定の心理的整合率**：プロジェクトタイプとテーマの適合率｜目標90%以上
2. **図解選定の1対1対応順守率**：診断カテゴリと図解パターンの対応率｜目標100%
3. **視覚階層の明瞭度**：8色階調の役割分業が実装に反映されているか｜目標WCAG AA全項目クリア
4. **要素数上限の遵守率**：Miller's Law（7±2）に基づく要素数制限の遵守率｜目標95%以上

これらは、β二次募集時・初回購入者提出時・30日運用時点の3ポイントで継続測定します。**「設計哲学が実装に体現されているか」を、感覚ではなく数字で担保する運用** を続けます。
