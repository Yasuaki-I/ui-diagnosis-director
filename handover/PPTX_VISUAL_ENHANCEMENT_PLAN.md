## 🔬 T-A：matplotlibレーダーチャート試作

### タスク内容
**現状のC-1スコアカードに、matplotlibで生成したレーダーチャート画像を組み込む技術検証。**

### 目標品質基準（target_image_02_scorecard.png より）
1. **二重線可視化**：青実線（実測値、塗り半透明）＋赤点線（理想値=5点、破線）
2. **10項目ラベル**：外側配置、番号バッジ（1〜10）付き
3. **数値マーカー**：各頂点にスコア数値（例：3, 5）を明示
4. **同心グリッド**：1〜5の5段階同心多角形
5. **配色**：青基調（#0055??系）、赤点線は破線スタイル
6. **凡例**：「あなたのLP」「理想値（5点）」を上部に明示

### タイムボックス
**1〜1.5h**（着手日1回で完結・中断耐性設計）

### 実装ステップ（想定）
```
Step 1（10分）：matplotlib で最小レーダーチャート生成
  - 10項目のダミースコア（例：3, 4, 5, 3, 4, 3, 5, 4, 3, 4）
  - 青実線＋赤点線の重ね描画
  - 出力：PNG 1点

Step 2（15分）：見た目調整
  - フォント（メイリオ推奨）
  - 配色（NAVY基調、赤点線）
  - グリッド（1〜5の同心多角形）

Step 3（15分）：PPTXへの組み込み検証
  - python-pptx で生成したPNGをC-1スライドに配置
  - スライド全体のレイアウト整合性確認
  - フォント・色調がv15デザインシステムと整合するか確認

Step 4（15分）：品質確認
  - LibreOfficeでPNG化して視認確認
  - 目標イメージとの近接度評価
  - 課題があれば1回イテレーション

Step 5（15-30分）：入江さん確認・満足度判断
  - 「発売バージョンに組み込むか」の判断
```

### 成功基準（3つのチェック項目）
- [ ] **ラベル崩れなし**：10項目のラベルが外側に読める形で配置される
- [ ] **二重線可視化**：実線（実測値）と点線（理想値）が明確に区別できる
- [ ] **PPTX内解像度・余白**：C-1スライドに配置した際に、余白・解像度が適切

### 分岐判断
- **成立（3つの成功基準クリア）** → T-Bへ進む・発売バージョンへの組み込み検討
- **物足りない（1つでも不合格）** → **画像対応（AI生成でスコアカード風画像を作成）** に切替

## 🔬 T-B：ビジュアル診断ボード質感試作

### タスクの前提（重要・入江さんとの合意）
- **見本（target_image_01）を1枚に収めるのは不可能** との前提で一致
- 既に v14/v15 で 3枚構成（LP構造マップ／スコア視覚化／Before-After）に分割済み
- **この骨格を活かし、各枚を見本の水準に引き上げる**
- ただし **デザインの空気感（余白・アイコンの質感・カラー階調）の完全再現はpython-pptxの構造的限界に触れる領域**
- レイアウト構造（Z型導線・配置バランス・カラールール）は踏襲可能だが、**ディテールの質感差は残る想定**

### タスク内容
**3枚のうち1枚（LP構造マップ推奨、または最も作りたい1枚）をタイムボックス試作し、PPTXでどこまで見本の質感に寄せられるかを実測。**

### タイムボックス
**1〜1.5h**（T-A成立後・別日での実施）

### 実装ステップ（想定）
```
Step 1（15分）：目標スライド1枚を選定
  - 案A：LP構造マップ（推奨・情報密度高くチャレンジング）
  - 案B：スコア視覚化（レーダーチャート含む・T-A成果活用可能）
  - 案C：Before-After版（プレゼン主役・比較的シンプル）

Step 2（15分）：現状スライドと目標イメージの差分洗い出し
  - カラー階調
  - 余白バランス
  - アイコンの質感
  - フォント使い分け
  - 情報密度

Step 3（30-45分）：改修実装
  - python-pptx でどこまで寄せられるか
  - アイコン挿入（絵文字・記号・SVG変換画像）
  - カラー階調の細分化
  - フォントサイズの階層強化

Step 4（10-15分）：LibreOffice描画確認
  - PNG化して見本と比較
  - 質感差の定量化（何が寄せられなかったか）

Step 5（15分）：入江さん確認・満足度判断
```

### 成功基準（入江さんの主観判断）
- [ ] **満足**：手法を残り2枚（スコア視覚化・Before-After）へ **横展開**
- [ ] **物足りない**：**デザイン面は画像対応（AI生成）が適切** として「奇跡の1枚」と同じ扱いに寄せる

### 分岐判断
- **満足 → 横展開** → 3枚構成すべてを新水準に引き上げ → **発売バージョンへの組み込み検討**（8月中旬〜下旬）
- **物足りない → 画像対応へ寄せる** → デザイン面はAI生成に任せ、Python側は情報の正確性に集中
