## ■ 2. 🔴 検出｜`score` の連番混入と配色単一化

### 2-1. ⚠️ 事象

⭐ **`timeline` 図解の各カードのスコア表示が意味をなしていない。**

| ⭐ カード | ⚠️ 表示 | ⭐ 説明文 |
|---|:---:|---|
| ⭐ FVに問い合わせCTAを常設 | ⚠️ **1%** | ⭐ 無料体験・問い合わせボタンをFV内に明示 |
| ⭐ 初心者向けキャッチへ修正 | ⚠️ **2%** | ⭐ 誰向けかを明確化し離脱を抑制 |
| ⭐ 中段・下段にもCTAを増設 | ⚠️ **3%** | ⭐ 検討後すぐ行動できる導線を追加 |
| ⭐ 料金比較と選び方を整理 | ⚠️ **4%** | ⭐ 初心者が迷わないプラン説明へ改善 |
| ⭐ 受講生の声を具体化・拡充 | ⚠️ **5%** | ⭐ 初心者の不安解消につながる実例を補強 |

⚠️ **併せて全カードが灰色一色で描画されている（⭐ 前回 9/2 午前は青系のグラデーションであった）。**

### 2-2. 🔴 原因1｜`score` に優先順位の連番が入っている

⭐ **GPT が `score` フィールドへ「⭐ 実施順（1〜5）」を入れたと推定される。** ⭐ **builder は `score` を「%」付きで描画する実装であるため、⚠️ 「1%」と表示された。**

**builder 5316行（`draw_timeline`｜逐語）**：

```python
            add_text(slide, cx + pad, cur, card_w - pad * 2, '%s%%' % score,
                     18, bold=True, color=txt_color, height_px=26)
```

⚠️ **「%」の付与は10箇所（⭐ 全図解パターン共通）に及ぶ。**

### 2-3. 🔴 原因2｜配色単一化は `_tier_fill` の警告オーバーライド（⭐ 案C 撤回の根拠）

**builder 3971-3978行（逐語）**：

```python
def _tier_fill(palette, score, base_key):
    """基準色 + 警告オーバーライド（原則②）。

    score が None の場合は警告判定をスキップする。
    """
    if score is not None and score < V17_WARNING_SCORE:
        return palette['warning']
    return palette[base_key]
```

⭐ **`V17_WARNING_SCORE = 40`（builder 3911行）。**

| ⭐ 今回の score | ⭐ `< 40` 判定 | ⭐ 結果 |
|:---:|:---:|---|
| 1／2／3／4／5 | ⭐ **すべて True** | ⚠️ **全カードが `palette['warning']` に倒れる** |

| ⭐ 前回（9/2午前）の score | ⭐ `< 40` 判定 | ⭐ 結果 |
|:---:|:---:|---|
| 30 | ⭐ True | ⭐ warning色 |
| 65／70／75／80／85／90 | ⭐ **すべて False** | ⭐ **`V17_SEQUENCE_TIERS` の階調が適用（⭐ 青系グラデーション）** |

🔴 **したがって配色単一化は「⭐ score が 40 未満」であることに起因し、⚠️ 「%」表記の有無とは無関係である。**

### 2-4. ⚠️ 案C（16往復目の一次見解）の撤回

| ⭐ 案C の内容 | ⚠️ 判定 |
|---|---|
| ⭐ **`score` が 0〜10 の場合は「%」を付けない** | ⚠️ **不適切** |

⚠️ **理由**：

| # | ⚠️ 問題点 |
|:---:|---|
| 1 | ⚠️ **配色単一化が解消しない**（⭐ §2-3 のとおり原因が別） |
| 2 | ⚠️ **`score=5` が「達成度5%」を意味する正当なケースと区別できない**（⭐ 値だけでは意図を判別不能） |
| 3 | ⚠️ **10箇所（全パターン）へ同型の分岐を入れることになり、⭐ 実装の複雑度が上がる** |
| 4 | 🔴 **根本原因（⭐ GPT が `score` の意味を知らない）が残る** |

⭐ **16往復目の案Cは、⚠️ `_tier_fill` を読まずに「%」表記だけを見て提示したものであった。** 🔴 **判断原理18（⭐ 実装を読んで確定させる）の適用不足である。**

## ■ 3. 🔴 案ζ｜Instructions 側での `score` の意味明示

### 3-1. ⭐ 根本原因

⭐ **lite v3.5.2 の J-7 には `diagram_data` の各キーの意味が記載されていない。** ⚠️ **これは 8/31 判定2 で「⭐ J-7-4 データ辞書は builder の `draw_*` docstring に実在する」として除外した項である。**

🔴 **除外の判断自体は妥当であった（⭐ 字数制約下で builder に情報があるものを重複記載しない）。** ⚠️ **しかし `score` の値域という「⭐ GPT が知らないと誤る情報」は、⭐ builder の docstring を読めない GPT には伝わらない。**

⭐ **`draw_timeline` の docstring（builder 5210-5228行）には `'score': int|None` とあるのみで、⚠️ 値域（0〜100）の記載がない。** 🔴 **つまり builder 側にも情報が不足している。**

### 3-2. 🔴 修正内容（⭐ 2箇所）

**① lite v3.5.2 の J-7 に1行追記（⭐ 約24字）**

```
`score`は0〜100の達成度/効果予測（40未満は警告色）。順位は入れない。
```

⚠️ **現在の残余は 24字。** ⭐ **上記は 36字であるため、⭐ 12字の追加圧縮が必要。**

**② builder の `draw_*` docstring に値域を明記（⭐ 14関数）**

```python
'score': int|None,   # 0〜100（達成度/効果予測）。40未満は警告色
```

⭐ **②は配布物の字数に影響しない。** 🔴 **PLAIN v3.5 の追随修正（⭐ 判定6）と同時に行える。**

### 3-3. ⚠️ 案ζ の限界

⚠️ **本案は「⭐ GPT が正しい値を入れる確率を上げる」ものであり、⭐ 誤入力を機械的に防ぐものではない。**

🔴 **より強固な対策として 案η（⭐ builder 側での値域検証）も考えられる**：

```python
# 案η（参考）: score が 0〜10 の範囲に全件収まる場合、
# 順位混入の可能性が高いため警告オーバーライドを無効化する
```

⚠️ **ただし案η は「⭐ 正当な低スコア（例：達成度5%）」を誤って救済する副作用がある。** ⭐ **統括判断を仰ぐ（§5 事項2）。**
