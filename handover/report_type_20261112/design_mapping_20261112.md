## 0. 前提の整理
- ガイドブックは**ダッシュボード（Power BI 中心）**向けの資料。今回の型は**PowerPoint の診断報告**であり、ガイドブックをそのまま適用するのではなく、**設計の原則を読み替えて使う**
- builder 内の記載（出典・色定義・「内部保持のみ・利用ロジック未実装」）は、出典を保持していたことを示すだけで、生成物に原則が適用されていた証拠ではない（判定245-2）。M2 の資料（Claude が作成）にも適用の指示はしていない
- ガイドブックに**明示的な記述がない**もの：文字サイズの絶対値、「余白」「揃え（アラインメント）」という語での規定、「注記や小さな文字への依存を避ける」という見出し。これらは近い記述からの読み替えとして扱い、「ガイドブックの規定」とは書かない

## 2. 対応表：型の要素 × 参照箇所 × 反映方法
### 2-1. 情報の優先順位（一目で分かる）
| 型の要素 | 参照箇所 | 要旨 | 反映方法（今回の型への読み替え） |
|---|---|---|---|
| 資料全体の並び（前提→全体像→提案→確認事項） | p.22「構造を伝える」、p.42–43 Do「全体の指標と詳細のグラフを表示する」 | 全体から部分へ。最初に全体を示し、次に詳細へ辿れるようにする | 全体像ページを提案ページより前に置く（r2 以来の構成と一致）。決裁者は全体像ページだけで「何が・どこで」を把握できるようにする |
| 各ページ内の配置 | p.23–24「レイアウトの考え方」 | 視線に合わせて左上から右下へ、全体から部分へ。左上で全体を端的に示す | 各ページの左上に「そのページの結論」（前提ページ＝目的とKPI、提案ページ＝課題の見出し）を置く。詳細（確認が必要なこと等）は右下・最下段へ |
| 強調 | p.39–40「強弱をつける」 | 重要な情報は色・サイズ・文字の太さで他と区別する | **独自方針**：各ページの主たる強調点を一つにする。見出し・現在位置・採否に影響する留保の強調は禁止しない。太さとサイズで階層をつけ、色は補助 |
| 載せる情報の選別 | p.18「載せるべき情報を選ぶ際の原則」、p.22「適切な情報量にする」、p.53 チェックリスト | 目的に当てはまらない情報は取り除く | 「画面で確認したこと」が空欄の候補は提案ページにしない（r4 §3-4）。検証手順は資料から外す（r4 §3-5） |

### 2-2. 揃った配置・余白・繰り返しの表現
| 型の要素 | 参照箇所 | 要旨 | 反映方法 |
|---|---|---|---|
| 配置の基準 | p.23「縦横6分割が可能なレイアウトグリッド（16:9）」、p.51「2〜6分割」 | 構成要素をグリッドに沿って置く | 16:9 を縦横に分割した共通の格子を全ページで使い、3列（画面で確認したこと／つまずきそうな点／改善の方向）は格子の3等分を基本案とし、情報量や画像の形に応じた調整を認める。※「揃え」という語の規定はガイドブックにない（読み替え） |
| 繰り返しの表現 | p.25「フィルターは上部か左部、影響を受ける情報はその下か右」 | 関係のある要素の位置関係を一定にする | 「検討する行動の流れ」の帯を全体像ページと提案ページの**同じ位置（上端）**に置き、その下に該当する内容を置く。提案ページ間で欄の位置・順序を変えない |
| 余計な要素を減らす | p.44 Do「不要な要素は削除する」（下地のグリッド・枠線を最小限、数値と直接関係のないテキストは薄く） | 情報の重複を避け、補助的な文字は薄い色に | 枠線・囲みは最小限にし、囲みの多用（M2 の資料で全欄が枠付き）を避ける。「つながり」等の補助行は本文より薄い色にしてよいが、読めるコントラストを保つ。採否に影響する留保（確認が必要なこと）を目立たなくする目的では使わない。※「余白」という語の規定はガイドブックにない（読み替え） |
| 並び順 | p.43（並び順に意味を持たせる。あいうえお順は Don’t） | 項目の順序に意味を持たせる | 全体像ページの提案は「行動の流れの段の順」に並べる。新たな優先度や工数では並べない（判定243-3） |

### 2-3. 色だけに頼らない意味の区別
| 型の要素 | 参照箇所 | 要旨 | 反映方法 |
|---|---|---|---|
| 色数 | p.36（10色のみ設定）、p.42 Do「色数を絞る」、p.53「1〜5色程度」 | 色数を絞る | 1つのカラーパレット（7系統から1つ）に限定し、役割（テキスト・背景・強調・補助）を固定する |
| 意味の区別 | p.42 Don’t「色のみで分類を識別しない」、p.43「白黒印刷しても伝わる」、p.38 色覚多様性 | 色以外（形・模様・文字）でも識別できるように | 「購入との関係」（直接に関わる段階／前段階）・「依頼者回答／未確認／診断側の提案」は**文字のラベル**で区別し、色は補助。現在位置の強調も太枠・塗り＋段名の文字で示す |
| コントラスト | p.38（背景と色面 3:1 以上、数値の文字は 4.5:1 以上） | アクセシビリティの基準 | 文字は背景に対して 4.5:1 以上、図形の色面は 3:1 以上を目安にする |
| 具体的な色の値 | カラーコード一覧（公式ページ・2026年7月17日更新）。ガイドブック p.35 の一部の値と差異あり（例：Blue 50） | 現行の値は公式ページ側 | 色の値を使う場合は公式ページの現行値を参照し、使用時点の更新日を記録する。builder 内の転記値は参照しない（取得日が古い可能性） |

### 2-4. 小さな文字や注記に依存しない情報量
| 型の要素 | 参照箇所 | 要旨 | 反映方法 |
|---|---|---|---|
| 簡潔な表記 | p.40「シンプルにする」「わかりやすく表記する」、p.42 Do「タイトルや凡例をシンプルに」 | 冗長な説明を取り除き、前提知識が要る表現を避ける | 欄名は平易な語（判定241 で了承済み）。各欄は短い文で、注記の重ね書きをしない |
| 補足情報の扱い | p.41「メタ情報を記載する」（ソース・更新日・いつ時点か・注釈・免責） | 補足は記載するが、本体と分ける | 「診断側が申告した確認範囲」「元データの診断日表記」等は、各ページの最下段の決まった位置に1行でまとめる。採否を左右する未確認事項は該当ページに1行、詳細は確認事項ページへ |
| 文字の大きさ | ガイドブックに絶対値の規定はない（記載なし） | — | 既存の試験・資料で指定してきた 14pt を「今回の型で用いる暫定下限」とする。社内全体の確定規則とは呼ばず、14pt なら読みやすいという保証にも使わない。ガイドブックの規定とは書かない |

## 3. 利用条件（実際に使うものごと｜判定245-2）
| 使う可能性があるもの | 条件（委託調査の結果・統括未照合） | 今回の型での扱い |
|---|---|---|
| ガイドブック本体の**考え方**（設計の原則） | PDF・代替テキストに個別のライセンス表記はなく、デジタル庁サイトのコピーライトポリシーにより PDL1.0 が適用（権利表記がない場合）。加工した場合は出典に加えて加工の主体を記載 | 考え方を参考にするだけで、図・文章を転記しない。資料に参考資料として名前を書く場合は出典の形に従う |
| カラーコード（公式ページ） | 公式ページの掲載情報として PDL1.0（同上）。数値データ等は著作権保護の対象外とされる旨の記載が PDL1.0 にある | 色の値を使う場合も、出典の書き方は使用時点の公式ページで再確認する |
| Power BI テンプレート（.pbit）・テーマ（.json） | GitHub README に PDL1.0 の明示あり。加工して使う場合は出典の明記不要、無加工で公開する場合は出典を記載 | **今回は使わない**（PowerPoint の型であり、Power BI ファイルは対象外） |
| 関連資料の PowerPoint（要件定義ワークシート・プロトタイプ作成ツール） | 個別のライセンス表記なし（PDL1.0 の適用）。**表紙やヘッダーにデジタル庁ロゴが埋め込まれている** | 今回は使わない。使う場合もロゴは PDL1.0 の対象外（使用には申請・許諾が必要）のため取り除く |
| デジタル庁ロゴ | PDL1.0 の対象外。使用には申請・許諾が必要 | **使わない**。公式資料・公式評価と誤認される見せ方をしない（判定241-4） |
- GitHub の .pbit・.json 用の規定（出典の扱い）を、ガイドブックや PowerPoint 資料に一括で当てはめない（判定245-2）

## 4. 入江さんの M2 所見への回答（整理）
