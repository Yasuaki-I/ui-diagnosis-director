- 依頼者回答は、実際に回答があった項目に限る。「進めてください」で了承された提案は**提案欄に残し**「依頼者了承」と付記する。了承は調査結果への格上げではない（判定241-2・3①）
- 「ECとして、KPIはCV（購入）」はスキル側が示した選択肢を依頼者が選んだ回答。この経緯を内部記録に残す

### 2-2. 今回想定する利用者（診断側の提案）の書き方
- 優先するのは、**提案に関係する行動と条件**：利用目的／探し方（カテゴリから・検索から・特集から）／購入判断に必要な情報（サイズ・在庫・到着日・レビュー等）／主に使う端末
- 名前・年齢・職業は埋めない。Webリテラシーは、課題との関係を説明できる場合だけ置く
- 表示の型：
  > 今回想定する利用者（診断側の提案）
  > ［利用目的・探し方・判断に必要な情報］
  > この想定で改善案を検討します。実際の利用者像は未確認です。
- 依頼者了承後は「診断側の提案・依頼者了承」と付記
- 具体的な想定の文言は、題材の原資料（10/31 のヒアリング・診断結果）と照合して次の段で作る。本書では型だけ示す

### 2-3. 行動段階の図

- この図を、2ページ目と提案ページで**共通の現在位置表示**として使う（§5）

## 3. 2ページ目：診断結果の全体像
| 欄 | 内容 |
|---|---|
| 段階 | 見つける／選ぶ／買う |
| 提案 | 1行の見出し |
| 購入との関係 | **購入操作に直接関わる段階**（例：カート・購入ボタン）／**購入の前段階**（例：商品にたどり着く）／**関係を説明できない** |

- 関係を説明できない課題は主要提案から外し、6ページ目へ（一律除外はしない）

### 4-1. 根拠の内部整理（スライドには全部を並べない｜判定241-3②）
提案ごとに、作成時の記録で次の3つを分けて持つ
| 区分 | 例 |
|---|---|
| 画面で確認した事実 | 特集バナーに行動ボタンがない（確認した画面・日時） |
| 依頼者が回答した目的・認識 | 目的＝EC、KPI＝購入CV |
| 行動上のつまずき・KPIへの影響についての仮説 | 次の行動先が見えず、商品へ進まない人がいるおそれ |
- スライドの「画面で確認したこと」は1行目、「つまずきそうな点」は3行目に当たる。2行目は1ページ目に集約し、提案ページでは「つながり」で参照する

## 5. デザインの独自要素（判定241-4）
装飾ではなく、提案を読み解くための共通表現に持たせる
1. 「見つける→選ぶ→買う」の現在位置（1・2・3〜5ページで同じ図）
2. 画面上の着眼箇所と提案番号の対応（同じ色・同じ番号の印）
3. 各提案ページで統一した「画面で確認したこと→つまずきそうな点→改善の方向」の3列
- デジタル庁のデザインシステムは、色・文字・余白の基準として使う案。ロゴ等は使わず、公式資料と誤認される見せ方を避ける。参照資料と利用条件は別途確認（未確認）

### 6-2. 載せ方
- 2ページ目：隅に1行の参考値（確認日・回を明記）。課題や効果の根拠として使わない
- 7ページ目（付録）：10項目の点、算出式、ランク基準、限界
  - 限界：画面確認による採点で、アクセス解析・利用者調査を含まない／採点者（AI）の判断を含む／確認した画面の範囲（決済画面は未確認）／同じサイトでも回によって点が変わる（36 と 34 の例）
- しないこと：独自の再計算、購入CV改善率への読み替え、点数による提案の順位づけ
- 掲載する回は、統括の照合後に入江さんが決める
