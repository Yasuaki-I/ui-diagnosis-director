## 0. この構成案の考え方
| 原則 | 内容 |
|---|---|
| 読み手 | 経営陣など裁量を持つ多忙な人。**1枚目で前提、2枚目で全体像**がわかる |
| 前提 | こちらの仮定ではなく、**依頼者の回答**を起点にする。回答がない項目は「未確認」のまま示し、埋めない |
| 区分 | 「依頼者回答」「未確認」「診断側の提案」を分ける（判定240-3） |
| 根拠 | ヒアリング・行動段階・KPI とのつながりで説明する。ただし、つながりの説明は**購入CVへの影響が確認されたことではない** |
| 提案 | 何を変えるかは明確に言う。効果の断定とは分ける |
| 留保 | 採否に影響する未確認事項は提案側に短く残す。詳しい検証手順は資料から外し、別記録にする |
| 言葉 | 欄の名前は平易にする（M2 の所見：「見えること（事実）」「困りうる場面（仮説の例）」がわかりにくい） |

## 1. ページ構成（基本形：提案3件の場合 6〜7ページ）
| # | ページ | 役割 | 必須／任意 |
|:-:|---|---|:-:|
| 1 | 診断の前提（ヒアリングのまとめ） | 何のために・何を・どの範囲で見たか | 必須 |
| 2 | 診断結果の全体像 | 提案の一覧を行動段階の上に並べ、1枚で俯瞰 | 必須 |
| 3〜 | 改善提案（1件1ページ） | 画面の事実 → つまずきそうな点 → 改善の方向 | 必須 |
| 末 | 確認が必要なこと | 関係が未確認の課題、未確認のヒアリング項目、次に確かめること | 必須 |
| 付録 | 点数（併記する場合） | 算出根拠と限界 | 任意（§5） |

## 2. 1ページ目：診断の前提（ヒアリングのまとめ）
**構成**：左に3区分の表、右に行動段階の図、下に確認範囲

### 2-1. 3区分の表（例示：ユニクロ）
| 項目 | 依頼者回答 | 未確認 | 診断側の提案 |
|---|---|---|---|
| サイトの目的 | EC（オンラインでの商品購入） | | |
| 重視するKPI | CV（購入） | | |
| 想定ユーザー | | 未確認 | （提案する場合のみ「提案値」と明記。名前・年齢・Webリテラシー等は埋めない） |
| 現状の課題感 | | 未確認 | |
| 診断の軸 | | | 機能軸 |
| 診断対象 | | | ユーザー導線／情報設計／CV導線 |
| 軸を選んだ理由 | | | KPIが購入CVのため、「見つける→選ぶ→買う」の各段階のつまずきを機能単位で見る |
| 診断の粒度 | | | 浅く広く（初回の全体把握） |
- 「依頼者回答」は、ヒアリングで実際に回答があった項目に限る（判定240-3）
- 診断側の提案のうち、依頼者が了承したもの（例：「進めてください」）は「提案（依頼者了承）」と示す案

### 2-2. 行動段階の図
- 「見つける → 選ぶ → 買う」の3段を横に並べ、各段の下に診断対象を置く
  - 見つける：ユーザー導線（トップから商品にたどり着くまで）
  - 見つける／選ぶ：情報設計（カテゴリ・検索・キャンペーン情報の整理）
  - 買う：CV導線（商品詳細からカート・購入まで）
- この図は**診断の見方の枠組み**で、実際の利用者行動を調べた結果ではないことを、図の見出し「診断の枠組み（診断側の提案）」で示す（長い注記にしない）

### 2-3. 確認範囲（1行）
- 例：「確認した範囲：〇年〇月〇日時点の公開画面（PC表示・トップ〜商品詳細〜カート）。アクセス解析・利用者調査は含まない」

## 3. 2ページ目：診断結果の全体像
**構成**：行動段階の帯（1ページ目と同じ図）の下に、提案を段階ごとに配置
| 欄 | 内容 |
|---|---|
| 段階 | 見つける／選ぶ／買う |
| 提案 | 1行の見出し（例：検索欄に入力の手がかりがない） |
| KPIとの関係 | **直接**（購入の手順そのものに関わる）／**間接**（購入に至る前の段階に関わる）／**関係未確認** |
| 裏付けの範囲 | 画面で確認／画面＋依頼者回答／未確認 |
- 「関係未確認」の課題は主要提案に入れず、末ページ「確認が必要なこと」へ回す（一律に除外はしない。判定240-3）
- 点数を併記する場合の位置は §5

## 4. 3ページ目以降：改善提案（1件1ページ）
**構成**：上に段階の印と見出し、中央に画面画像（広く）、その下に3列、最下段に関係と裏付け
| 部品 | 欄の名前（案） | 内容 |
|---|---|---|
| 段階の印 | （図の一部） | 2ページ目の帯の該当段を強調した小さな図。どこの課題かが一目でわかる |
| 見出し | — | 課題を1行で言い切る（例：分類の枠に、手続きの例がない） |
| 画面 | — | 対象箇所の画像。位置図は必要な場合だけ（M2 の所見：右上の位置図が判別しづらい） |
| 列1 | **画面で確認したこと** | 観察した事実。確認した画面・範囲に限って言い切る |
| 列2 | **つまずきそうな点** | 困りうる行動上の問題。依頼者回答や段階と結びつけて書く。「〜しそう」「〜のおそれ」と、断定しない語尾で |
| 列3 | **改善の方向** | 何を変えるかを明確に。効果は断定しない |
| 最下段 | **つながり** | ヒアリング項目（例：KPI＝購入CV）・段階（例：見つける）・KPIとの関係（直接／間接） |
| 最下段 | **確認が必要なこと** | 採否に影響する未確認事項を1行（例：スマートフォン表示は未確認） |
- 載せないもの：Before/After の画面、効果の数値、根拠のない順位・重要度
- 「仮定上の判定」（〇△×）は置かない案。代わりに「つながり」と「確認が必要なこと」で根拠と限界を示す（M2 の所見：仮定上の判定は根拠として弱い）。〇△×を残すかは相談事項（§7）

## 5. 点数の扱い（併記する場合の案）
現状：暫定案(b)（〇△×＋平易な説明＋図）。点数併記の希望は取り下げていない。ユニクロの例の「36/50・ランクB」は原資料未確認で、本案では数値を使わない
| 案 | 位置 | 長所 | 短所 |
|---|---|---|---|
| A 付録のみ | 付録ページに点数・算出根拠・限界 | 本文の根拠と混ざらない | 決裁者が見落としやすい |
| B 全体像に参考値 | 2ページ目の隅に「参考：〇/50（算出方法は付録）」 | 一目で水準がわかる | 点数が結論のように読まれるおそれ |
| C 併記しない | — | 誤読がない | 点数併記のご希望に応えられない |
- どの案でも守ること：**点数だけを課題や効果の根拠にしない**（判定240-4）／算出根拠（観点・配点・誰がどう採点したか）と限界（画面確認のみ、利用者調査なし、採点者の主観を含む等）を必ず付録に書く

## 6. 検証記録の分離
- 判読対象・表示条件・測定値・照合などの検証手順は資料に載せず、別の記録（記録表）に残す
- 資料には、採否に影響する未確認事項だけを短く残す（判定239-3の線引き）

## 7. 入江さんと相談したいこと
