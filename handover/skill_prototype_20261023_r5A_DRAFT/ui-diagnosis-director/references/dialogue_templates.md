# 会話の文面（このとおりに使う）

## 確認A（ヒアリングの要約｜4行・長くしない）
```
ヒアリング内容を以下のように理解しました。齟齬があればお知らせください。

- サイトの目的：{目的}
- 重視するKPI：{KPI}
- 想定ユーザー：{ユーザー像 or "未確認"}
- 現状の課題感：{課題感 or "未確認"}

上記で問題なければ、次に診断観点をご提案します。
```
- 「はい」「OK」「進めて」など、はっきりした同意があってから次へ。直しの希望があれば要約を直して再確認

## 必須2項目が2回聞いても得られないとき
```
{目的 or KPI}については、以下の前提で進めます。
- サイトの目的：{仮の値／例：EC}
- 重視するKPI：{仮の値／例：CV率向上}

違えば途中で仰ってください、その時点で軌道修正します。
```

## 観点の提示と確認B
| 軸 | 構成 | 合う場面 |
|---|---|---|
| 時系列軸 | 現状／課題／改善案 | 経営層への報告・全体像 |
| 機能軸 | ユーザー導線／情報設計／CV 導線 | CV 改善・導線設計 |
| 体験軸 | ファーストビュー／回遊／離脱防止 | 回遊率・滞在の改善 |
| デバイス軸 | モバイル／PC／タブレット | レスポンシブ・スマホ |
- 粒度：初回・全体像なら「浅く広く」／特定の課題の深掘りなら「深く狭く」
```
今回は{種類}として診断します。
ヒアリング内容を踏まえて、以下の3観点で診断を進めるのが最適と判断しました。

■ 診断の軸：{軸名}
■ 3つの診断対象：
  1. {対象1}
  2. {対象2}
  3. {対象3}

■ この軸を選んだ理由：
{ヒアリングと結びつけた理由を1〜2文}

■ 診断の粒度：{浅く広く / 深く狭く}

この3観点で診断を進めてよろしいですか？
差し替え・追加があれば教えてください。
```
- はっきりした同意があるまで生成しない。差し替えはヒアリングに戻らず、軸だけ直して再確認

## E1. URL が読めない
```
恐れ入ります。{URL} にアクセスを試みましたが、ページの内容を読み取れませんでした。

以下のいずれかで診断を進められます：
【方法1・推奨】画面のスクリーンショットをお送りください
【方法2】同じサイトの別ページのURLをお送りください
【方法3】数分後に再度お試しください

どの方法で進めましょうか？
```
- **読めないまま推測で採点しない**

## E2. 種類が分からない（画像1枚など）
```
お送りいただいた画像について、診断対象の種類を確認させてください。
- LP / EC / コーポレート / SaaS：全10項目で診断
- バナー：5項目（FV・キャッチ・CTA・信頼性・ブランド一貫性）で診断
- その他：当てはまる項目のみ診断
ご指定がなければ、こちらで判断して進めます。
```

## E3. スクリーンショットが読み取れない
```
お送りいただいた画像から、診断に必要な要素を読み取れませんでした。
- ページ全体のスクリーンショット（縦長のキャプチャがおすすめです）
- 画質を上げての再送
- URL の併用
のいずれかをお試しください。
```

## 生成のあと・途中の依頼
- 生成中の観点・種類・素材の変更：「現在生成中のため、完了後に再診断で対応します」
- 生成後の修正：採点は交渉の対象外／観点の漏れなら再診断／言い回しの修正は受ける
- 二次成果物（FV のワイヤー・Before/After・デザイナー向け指示書など）：生成の前に1回だけ「{名前}を{構成}でまとめます。この形式でよろしいですか？」と確認。デザイナー向け指示書はテキストで納品（PPTX は頼まれたときだけ）
