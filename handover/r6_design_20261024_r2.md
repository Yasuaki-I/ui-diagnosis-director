## 2. 文字種と単位の規則（判定106-2）

### 2-1. 表示幅（C の数え方）
| 文字種 | 判定のしかた | 表示幅 |
|---|---|---:|
| ASCII の印字文字（U+0020〜U+007E：英数字・記号・半角スペース） | コードポイントで判定 | 0.5 |
| 全角英数・全角記号・ひらがな・カタカナ・漢字 | 上記以外で、Unicode の East Asian Width が W または F | 1.0 |
| 曖昧幅（A）の記号（①・※・○・◎・→・●・■・◤・⚠ など） | East Asian Width が A | **1.0**（日本語フォントでの表示に合わせる） |
| 全角スペース（U+3000） | — | 1.0 |
| 半角カナ（U+FF61〜U+FF9F） | — | **入力では NG**（理由：「半角カナは全角に直す」）。builder は1.0、表示は0.5相当で、数え方が食い違うため |
| 改行・タブ（U+000A・U+000D・U+0009） | — | **入力では NG**（どの欄でも。builder は一部で改行を空白に置き換えるため、意図しない表示になる） |
| 結合文字（U+0300〜U+036F）・異体字セレクタ（U+FE00〜FE0F）・ゼロ幅（U+200B〜U+200D）・私用領域・制御文字・絵文字（U+1F000 以降） | — | **入力では NG**（理由を名指しする）。黙って取り除かない |
| 上のどれにも当たらない非ASCII（East Asian Width が N・Na・H の文字。例：✓ U+2713・✕ U+2715・⚠ U+26A0 などを**入力に**書いたもの） | — | **入力では NG**（理由：「未対応の文字種」）。黙って取り除かない。表示の欄に記号が要るときは、§2-2 の固定記号として builder が描く |

- **判定の順番（判定110 条件2）**：①§2-2 の**固定文言・固定記号の一覧**を先に当てる → ②当たらない文字に §2-1 の文字種の規則を当てる。✓・✕・⚠ は East Asian Width が N、→ は A なので、「A だけを許す」条件にはしない。
- **この表は表示の欄の入力に使う**。非表示の `record`（正式名称・URL）には当てない（§5-2）。

### 2-2. 2つの表の役割を分ける（判定110 条件2）
| 表 | 対象 | 使い方 |
|---|---|---|
| **固定文言・固定記号の一覧** | builder が自分で描く記号・文言（✓・✕・→・◎・⚠・◤・●・「工数：」「箇所：」「現状　」「改善後　」「BEFORE」「AFTER」「POINT」「優先度」「良好」「要改善」・欄の名前・題名など）と、句点の前の U+2060（幅0） | 実装のときに builder 17.2.17 の文字列から作り、記録に載せる。固定記号の幅は一覧に書いた値で数える |
| **枠の対応表**（§4） | PPTX の各文字枠・表セル | 各枠を「入力の欄／固定文言／例外」のどれか1つに結び付ける |
- **可変の入力の文字**（サイト名・所見・強みなど）は、固定文言の一覧とは照合しない。§2-1 の文字種の規則と、入力との照合（§3-4）で扱う。
- 未検査で止めるのは次の場合だけ：①入力の欄の文字に、§2-1 で定義されていない文字種が PPTX 上で現れた（入力の段階で止まらなかった＝想定外）②固定文言として結び付いた枠に、一覧に無い文字がある ③入力にも固定文言にも結び付かない枠（§4-1）。いずれも理由を示す。

### 2-3. 単位の換算
| 対象 | 換算 |
|---|---|
| 座標 | スライド幅の EMU ÷ 1280 で px に直す（`emu × 1280 / slide_width`） |
| 文字の大きさ | pt × 4/3 ＝ px（14pt＝18.67px、18pt＝24px） |
| 段落の前後の間隔 | `spcBef`／`spcAft` の pt × 4/3 ＝ px（百分率の指定は、その段落の文字の大きさ × 割合） |
| 行の間隔 | 倍率（`spcPct`）：文字の大きさ px × 1.2 × 倍率／固定値（`spcPts`）：pt × 4/3 |
| 文字間隔（`spc`） | 1/100 pt × 4/3 を1字ごとに足す |
| 1つの段落に大きさが混在 | 行の高さは、その段落の**最も大きい文字**で代表する。幅は文字のまとまりごとに足す |
| 入力の上限 | 表示幅（全角換算）。A（len）とは別に数える |

## 3. 幅・高さの点検（判定106-3・107）

### 3-1. 幅（1行必須の欄）
- 文字枠の幅から左右の余白（`lIns`／`rIns`。builder は0）を引いた値を使う。表のセルは、列の幅からセルの余白を引く。
- 段落の幅＝Σ（文字のまとまりの文字の大きさ px × 表示幅）＋文字間隔。
- 幅 ≦ 枠の幅 → 基準内／超える → **NG**。
- 段落の中に改行（`<a:br>`）があれば、1行必須の欄では **NG**。

### 3-2. 高さ（複数行を許す欄と、複数の段落がある枠）
- 枠の高さから上下の余白（`tIns`／`bIns`）を引いた値を使う。
- **通常の推定（NG を決める計算）**：段落ごとの行数＝ceil（幅 ÷ **有効幅**）。有効幅＝枠の幅−左右の余白。高さ＝Σ（行数 × 行の高さ）＋段落の前後の間隔。空の段落も1行として数える。この高さが枠の有効高さを超えたら **NG（高さ超過）**。
- **補助の判定（余裕の不足を知らせる計算）**：行数＝ceil（幅 ÷（有効幅 − 文字の大きさ1字分））で数え直す。これは禁則（行頭の「、」「。」などの送り）と単語の送りへの**仮定**である。通常の推定では収まるが、補助の判定では行が増えて枠を超える欄は、**NG にせず「要実機確認（折り返しの余裕不足）」**とする。補助の判定だけで NG にはしない（判定110 条件1）。
- 例：フローの説明9字（168px）・枠180px → 通常の推定では1行、見出しとの合計 51.52px で枠56px の中（基準内）。補助の判定では2行・合計78.4px となるため、「要実機確認（余裕不足）」。上限を短くして帳尻を合わせることはしない。
- **情報カード（「診断対象」＋値）・行動フロー（見出し＋説明）・構造マップ**のように、1つの枠に2つの段落がある欄は、横が各1行でも、**縦の合計**を点検する（例：フローの枠56px に、見出し 18.67×1.2×1.1＝24.6 と説明 18.67×1.2×1.2＝26.9 で計51.5px）。
- 行の間隔の指定が段落に無いときは、**1.0 と仮定**する。この仮定を使った欄は、結果に「行間：仮定1.0」と出す。その欄の高さの余裕が10%未満なら「基準内」とせず「**要実機確認**」とする。
- 1.2 は PowerPoint の「1行」の目安で、安全を保証する値ではない。

### 3-3. 簡易推定では扱えない形
| 形 | 扱い |
|---|---|
| ASCII の長い単語（空白を含まない英数字が、1行の入る量の1/3以上） | 複数行の欄：**要実機確認**／1行必須の欄：幅で点検（超えれば NG） |
| 明示の改行 | 1行必須：NG／複数行：段落を分けて数え、「明示改行あり」と出す |
| 大きさの違う文字が1つの段落に混在 | §2-3 のとおり数え、「大きさ混在」と出す |
| 継承をたどっても大きさが分からない | **未検査**（§5） |
- どの場合も「実際の行数が確定した」とは表示しない。

### 3-4. 入力との照合（切り詰めの検出）
- 各欄について、PPTX の文字が「入力の文字列＋builder の決まった接頭辞・つなぎ」と**完全に一致する**ことを確かめる。末尾が「…」になっていたら **NG**（B の制約に抵触）。

### 3-5. 結果の表示（判定107）
```

表示の簡易推定：基準内（N欄）／要実機確認（M欄・一覧）／NG（K欄・一覧）／未検査（U欄・一覧）

## 4. 入力項目と生成後の枠の結び付け（判定106-4）

### 4-1. 対応表（builder は変えずに、点検の側で持つ）
- 点検は、各ファイル・各スライドの**すべての文字枠（表のセルを含む）**を、図形の順に読み出す。
- 各枠を、次のどれか**ちょうど1つ**に結び付ける：
  1. **入力の欄**：ファイル・スライド番号・枠の位置（left／top／width／height を px に丸めた値、±2px）・期待される文字（入力＋接頭辞）の組で特定する。並びのある欄（強み・課題・構造マップ・フロー・提案・ハイライト）は、何番目かも対応させる。
  2. **固定の文言**：題名（【1】UI診断スコアカード など）・副題・欄の名前（診断対象・入力種別 など）・凡例・10項目の名前・スコア表記（n/5）・総合スコア・ランク・ページ番号（「n / N」）・フッター。
  3. **例外表**：§4-3。
- **どれにも結び付かない枠 → 未検査で停止**。**2つ以上に結び付く枠 → 未検査で停止**。**期待される欄が見つからない → NG**。都合よく除外しない。
- 位置の値は、r6 の実装のときに builder 17.2.17 の座標から作って表に固定する。builder の版が違えば、表と合わずに未検査で止まる。

  "record": {
    "service_name_official": "正式名称（文字列・空は不可）",
    "target_url": "https://…（文字列）または null",
    "input_origin": "url" または "screenshot"
  },
  "diagnosis": {…}, "proposals": {…}, "visual_data": {…}
}
```
- `record` は input.json の**いちばん上**に置く。builder には渡さない（builder は diagnosis・proposals・visual_data だけを受け取るので、PPTX には出ない）。
- `record` は**非表示の記録**なので、表示の欄の字数上限（§1）や文字種の制約（§2-1：半角カナ・曖昧幅など）は当てない。型・必須かどうか・入力種別との整合・URL の形だけを確かめる（判定110 条件2・判定111-2）。

### 5-2. 必須の条件（点検で確かめる）
| 条件 | 違反のとき |
|---|---|
| `record` が無い、または型が違う（`service_name_official`・`input_origin` は文字列、`target_url` は文字列か null） | NG |
| `input_origin` は **`url` か `screenshot` のどちらか**。欠落・それ以外の値 | NG |
| `service_name_official` は**全案件で**空でない文字列 | NG |
| `input_origin` が url → `target_url` は空でなく `http://` か `https://` で始まる | NG |
| `input_origin` が screenshot → `target_url` は null でよい。`input_type` に「スクショ」を含む | NG |
| `input_type` に「URL」を含む ⇔ `input_origin` が url | NG（食い違い） |
| C-1・C-2・C-3 の `service_name` が3か所で同じ | NG |
| `service_name` が A・C を満たす（§1-2） | NG |

### 5-3. 生成の手順（AI の仕事・SKILL.md に書く）
- 架空の URL を作らない。URL が分からないときは null とし、`input_origin` を screenshot にする。
- 正式名称が11字を超えるときは、**意味を変えずに**表示名を作り（例：「ユニクロ公式オンラインストア」→「ユニクロ公式オンライン」）、購入者に「表示名を『〇〇』にしました（正式名称：〇〇）」と1行で知らせる。
- 正式名称と表示名が同じなら、知らせなくてよい。

### 5-4. 点検の役割
- 点検は**必須の条件**だけを確かめ、表示名と正式名称が違うときは**両方を報告に出す**。言い換えの意味が妥当かどうかは判定しない（AI の手順で確かめる）。

## 6. 試験（判定106-6）
**すべての試験で、止まった欄と理由が期待どおりかを確かめる**。無関係な NG で止まっただけでは、試験の合格としない。正常な試験では、NG と未検査の両方が **0** であることも確かめる。

### 6-0. 2種類の試験を分ける（判定110 条件3）
| 試験 | 対象 | やること | やらないこと |
|---|---|---|---|
| **旧PPTXの回帰試験**（§6-1・§6-2） | 元の PPTX 3点（/tmp に写したもの） | 幅・高さ・枠の対応・旧フッター・枚数を、**PPTX だけで**調べる | 入力 JSON・`record` の点検（元の入力は手元に無い。`record` は r5 に無い）。これらが無いことを理由に、表示の点検を止めない |
| **新入力の生成前の検査**（§6-3〜§6-5） | r6 用に作った入力 | A・B・C・文字種・`record`・生成・PPTX の点検まで一式 | — |
- 点検の作りとして、**PPTX の表示の点検は、入力の点検の結果に関わらず必ず最後まで実行**し、両方の結果を3段の表示に出す。
- 再構成した入力を使う場合は「再構成入力（原入力ではない）」と明記し、実行した検査とできなかった検査を記録する。新しい上限（強みの28換算など）で入力側の NG が出ても、PPTX 側の正常な複数行の試験とは分けて記録する。

入力の項目は5つだが、生成後の出現は**6か所**。幅・高さ・フッターは**別々に**確かめる。全体の終了コードが0でないことだけでは合格にしない。各期待値を1つずつ照合する。

## 7. 必要な情報が取れないときは「未検査」で止める
次のどれかに当たれば、その欄は**未検査**とし、全体を不合格（終了コード≠0）にする。合格の表示は出さない。
1. 文字の大きさが、まとまり・段落・枠・継承のどこからも分からない
2. 枠の幅・高さが取れない、または0
3. 枠がどの欄にも結び付かない、または2つ以上に結び付く（§4-1）
4. §2-2 の①〜③に当たる（定義されていない文字種が入力の欄に現れた／固定文言の枠に一覧に無い文字がある／どこにも結び付かない枠）
5. PPTX が開けない、またはファイルごとの枚数が想定と違う（§4-2）
- 報告には、未検査になった欄・ファイル・スライド番号・理由を出す。
