## 2. 段階①で作りたい1枚（構成案）
**成功の条件（統括の意見 2 の文のまま）**：初めて見る人が、元の画面・問題箇所・問題の理由・改善の方向を対応づけて理解できる1枚。

確かめる点：
1. 番号と指摘箇所が正しく対応している
2. 画面画像と文字が読める
3. 事実と推測が区別されている
4. 入江さんが口頭で補足しなくても、要点が伝わる

構成案（たたき台）：
| 場所 | 中身 |
|---|---|
| 左（大きく） | 実際の画面の画像。問題の箇所に番号（①②③）と枠 |
| 右 | 番号ごとに「何が起きているか（事実）」「なぜ困るか（理由）」「どう直すか（方向）」の3行。推測は「推測」と書き分ける |
| 下 | ひとことの結論（最優先の一手） |

- 指摘は**重要な少数（目安3つ）に絞る**。多数を詰め込まない（統括の意見 2）
- 今の PPTX 3点（スコアカード・改善提案・ビジュアルボード）は変えずに残し、この1枚を**別に試す**形にする

## 3. 想定利用者と、求める準備
| 想定利用者 | 渡すもの | 受け取りたいもの | 求めてよい準備 |
|---|---|---|---|
| チャットで使う人（Web担当・ディレクター・広報担当など） | URL、または画面のキャプチャ画像 | 説明に使える資料 | ほぼなし（今と同じ） |
| 開発環境を使う人 | URL | 資料と、検証の記録 | 開発環境の準備を許容する |

- 選ぶ基準は「Claude Code だから高機能」ではなく、**利用者にどこまで準備を求めるか**（統括の意見 3）
- 開発に使う環境と、完成したスキルを利用者が使う環境は分けて考える

## 4. Claude ／ Claude Code の比較と未確認事項
考え方：**共通の診断手順**（何を見て、どう採点し、どう説明するか）と、**環境ごとの画像取得・生成の処理**を分ける（統括の意見 3）

| | Claude（今のスキル） | Claude Code |
|---|---|---|
| 向いている利用者 | チャットで URL や画像を渡して資料を受け取りたい人 | 準備を許容し、ブラウザ操作・ファイル管理・検証まで組みたい人 |
| 4件目で分かっていること | Claude はブラウザで3通りの幅の画面を見ていた（画面13〜14）。コードを実行する側の外部接続は「パッケージマネージャーのみ」（画面04） | 入江さんの環境では未確認 |
| 未確認 | 下の (1)〜(5) | 下の (1)〜(5) |

- スキルは指示・スクリプト・資料をまとめる仕組みで、外部への接続とは別。スキルにしただけで、画像の受け渡しや通信の制限が解消するわけではない（統括の意見 3）

**画像について、分けて確かめること（統括の意見 4）**
1. URL を読み取れる
2. ブラウザで画面を見られる
3. その画面を画像ファイルとして保存できる
4. 生成の処理が、そのファイルを読み込める
5. 元の画面と注釈を対応づけて出力できる
- 「見えている」（2）だけでは、（3）（4）が成り立ったとはしない
