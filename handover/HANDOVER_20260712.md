#### 発端
入江さんから共有された C-3 slide1 スクショで、「◎ 強み（活かすべき点）」の項目「明確な CTA ボタンとファーストビュー設計」が **「設」と「計」で折返した2行目の間隔が広く、1文の続きに見えない**問題を指摘。

#### 根本原因（技術的）
python-pptx の `paragraph.line_spacing` が **段落内の全行に適用** されるため、v14までは「1項目内の折返し行間」と「項目間の分離余白」を **同じ1.6-1.7で制御** していた。結果、折返しが発生すると項目内も項目間と同じ間隔となり、視覚的な連続性が失われていた。

#### 修正方針（案A採用）
`_add_multi_run_box` / `add_paragraph_box` に `space_after_pt` / `space_before_pt` / `vertical_anchor` パラメータを追加し、**line_height（折返し行間・タイト）** と **space_after_pt（項目間余白・広め）** を独立制御可能に。

## 🔍 発見したこと

### 技術的発見
- **python-pptx の `line_spacing` は段落内制御専用**。段落間余白は独立して `space_after` / `space_before` で制御すべき。CSSの `line-height` と `margin-bottom` の関係と同じ原則。
- **v14までの実装は「1行運用厳格化」で折返しを回避していた**が、境界値ギリギリのテキスト（22字上限）では LibreOffice 描画差で稀に折返しが発生していた。今回の分離制御はこの副作用も救済している。
- **vertical_anchor=MIDDLE の有用性**：1行運用のテキストを幅広の帯内に配置する場合、上下余白の視覚的均衡化にこれが最善解。座標調整より圧倒的にシンプル。

### プロセス的発見
- **「先行検証→水平展開」の順序が正解**：④のみで修正効果を実測してから残り5箇所に横展開したため、値（line_height=1.2, space_after_pt=8）の妥当性を早期に確認できた。時間ロスなし。
- **問題再現データの重要性**：C-3 gen_v10_final.py の strengths が短文（8-9字）だったため、当初は折返しが再現せず。元スクショと同じ長文（20-26字）に差し替えたことで検証可能に。今後の検証スクリプトも「問題再現用データ」を維持すべき。
- **入江さんの視覚判断力の高さ**：「差異が視覚的に薄い」との指摘は数値ベースで検証したところ、折返し行間22.4px vs 項目間33.1px（差 10.7px = 48%）と実測できた。「感覚」は正しかった。

### 認識齟齬の教訓
- 朝の時点で僕は「PPTXレイアウトのキャプション修正」を「Brain記事のキャプション追記」と混同 → 入江さんから2度の認識整合指摘で軌道修正
- 「1行超過時の表示ロジック」を当初は `replace('\n', ' ')` 問題と誤解 → スクショ確認で `line_spacing` 問題だと再定義
- **「実物スクショで問題を確認する」ステップを最初に踏むべき**だった。テキスト説明だけで対応方針を決めたのが遠回りの原因
