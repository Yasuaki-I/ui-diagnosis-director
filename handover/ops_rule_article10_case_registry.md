## 📌 事例001｜6章6.4節｜「精度100%は最初は信用できない数字だった」の自己開示

- 適用日：**2026-08-16（日）**
- 対象：Brain販売原稿 6章 6.4節
- 分類：**自己開示による信頼性担保**

### ① 状況

v3.5コアの55シナリオ総合テストで**総合精度100%（88/88 PASS）**を達成した。この数値をBrain販売原稿6章に記載する際、**「精度100%」という表記が購入者に不信感を与えるリスク**を検出した。実測値である以上虚偽ではないが、**販売文脈での「100%」は誇大表現と受け取られる**ことが一般的である。

### ② 検討した選択肢

| 選択肢 | 内容 |
|:---:|-----|
| A | 「精度100%」と**そのまま記載**する（実測値であり虚偽ではない） |
| B | 「高精度」等の**定性表現に置き換える**（数値を出さない） |
| C | **100%と明記し、同時に「最初は信用できない数字だった」と自己開示**する |

### ③ 却下理由

- **A却下**：実測値であっても、購入者の第一反応は「本当か」である。数値の正しさと**受け取られ方は別問題**であり、説明なしの100%は不信の起点になる。
- **B却下**：定性表現への逃避は、**348検証項目全PASSという実装努力を自ら消す**行為。誠実さのために成果を隠すのは本末転倒。

### ④ 採用根拠（選択肢C）

**「私自身が最初この数字を疑った」という事実を先に書く**ことで、読者の疑念を先回りして代弁した。疑念を持たれる前に自分が持っていたと示すことで、**数値の説明責任を果たしつつ実測値を維持**できる。

数値を下げず、隠さず、**受け取られ方の問題として処理**した。

### ⑤ 統括判定

✅ **承認発行（8/16 21:00 判定③｜事後承認）**

> 統括評価：「6.4節の自己開示は、**統括が12:00連結①で確認を求めた論点に対する最適解**｜この判断根拠の言語化を歓迎する」

## 📌 事例002｜7章｜月間ROI記述の条件明示化

- 適用日：**2026-08-17（月）**
- 対象：Brain販売原稿 7章
- 分類：**推計値の断定回避｜二文書運用の正式化**

### ① 状況

B-6本体6章6.5節には**月間ROIの断定的な金額推計**が記載されている。これをBrain販売原稿7章へ転用する際、**購入者の稼働単価・案件数によって金額が大きく変動する**ため、断定表記が実態と乖離するリスクを検出した。

### ② 検討した選択肢

| 選択肢 | 内容 |
|:---:|-----|
| A | B-6本体の**断定推計値をそのまま転用**する（第9条の逐語転記に忠実） |
| B | ROI記述を**削除**する（リスクを完全回避） |
| C | **削減時間は明示し、金額は条件明示**にする（「あなたの実務の規模で決まる」） |

### ③ 却下理由

- **A却下**：B-6本体は**思想マニフェスト**であり断定推計値の記載が許容されるが、**Brain販売原稿は購入判断材料**である。同じ数値が文書の性質によって適否を変える。
- **B却下**：削減時間（3〜6時間 → 0〜0.5時間）は**実測に基づく中核訴求**であり、削除は購入者への情報提供義務を放棄する。

### ④ 採用根拠（選択肢C）

**削減時間は実測値なので明示｜金額は購入者の条件で決まるので条件明示**という切り分けを行った。「**私が決められるものではなく、あなたの実務の規模で決まる**」と記述。

この判断は5章「4フェーズ判断木」の**判断主体思想（購入者が判断する）とも整合**しており、原稿全体の思想と矛盾しない。

### ⑤ 統括判定

✅ **事後承認発行（8/17 21:00 判定③）｜二文書運用として正式化**

| 文書 | 数値記述の方針 |
|-----|------------|
| **B-6本体6章6.5節** | **断定推計値を保持**（思想マニフェストのため許容） |
| **Brain販売原稿** | **条件明示に変換**する運用を**8/17付で正式化** |

## 📌 事例003｜7章7.5節｜GPT仕様変更への「無理な追記をしない」判断

- 適用日：**2026-08-17（月）**
- 対象：Brain販売原稿 7章 7.5節
- 分類：**「書かなかったこと」の品質判断化**

### ① 状況

統括より「外部プラットフォームの仕様変更が確認された。7章・8章・終章で商品設計の転換が必要」とのインプットを受領した。7章7.5節で**プラットフォーム非依存性を示唆する記述**を追加する必要が生じたが、**どこまで書くかの判断**が必要となった。

### ② 検討した選択肢

| 選択肢 | 内容 |
|:---:|-----|
| A | 仕様変更の**経緯と影響を丁寧に説明**し、非依存性の価値を厚く訴求する |
| B | **一節だけ肯定形で示唆**し、それ以上書かない |
| C | 仕様変更に**一切触れない**（従来記述のまま） |

### ③ 却下理由

- **A却下**：⚠️ **記述を厚くすると読者に「何かトラブルがあったのか」と推測させる逆効果**が生じる。7章の主題（5層統合）はもともとプラットフォーム非依存の設計思想であり、**過剰説明は「後付けの言い訳」に見える**。
- **C却下**：統括インプットを完全に無視することになり、**8章・終章の商品設計転換議論への接続点が失われる**。

### ④ 採用根拠（選択肢B）

**「それを作ったツールがどうなろうと」という一節だけで示唆は成立する**と判断した。

3つの実装方針を守った：①**プラットフォーム名ゼロ件**｜②**肯定形で語る**（「PPTXは業界標準｜あなたの資産として残ります」）｜③**設計思想として位置づける**（「ここは設計上の譲れない一点です」＝当初からの設計判断として提示し、外部環境変化への対応臭を排除）。

**書かないことによって、示唆の質を上げた。**

### ⑤ 統括判定

✅ **全面妥当と評価（8/17 21:00）｜⭐ 統括想定を上回る判断として登録指示**

> 統括評価：「『**無理な追記をしなかった判断根拠**』（読者に「何かトラブルがあったのか」と推測させる**逆効果の回避**）は**統括の想定を上回る判断**であり、**運用ルール第10条の適用事例として追加登録候補**」

**⇒ 本事例集の起票理由そのものとなった事例。**

## 📌 事例004｜AIドライブ書込後のサイズ表示不整合への自主対応

- 適用日：**2026-08-17（月）EOD**
- 対象：`NEXT_SESSION_PROMPT_20260818.md`（rev2配置時）
- 分類：**エスカレーション条件外の徴候の自主検出・自主対応**

### ① 状況

8/18プロンプトrev2（17,569B）をAIドライブへ配置した直後、**ファイルサイズが更新前の値（14,942B）のまま表示された**。配置成功と誤認したまま終業すると、**翌朝の起動時に旧版プロンプトを読み込み、統括補記5件が反映されない状態で8章転用に着手する**という連鎖リスクが存在した。

**エスカレーション条件(a)(b)(c)のいずれにも該当しない**事象であった。

### ② 検討した選択肢

| 選択肢 | 内容 |
|:---:|-----|
| A | サイズ表示の遅延と判断し、**そのまま終業**する |
| B | **統括判断を仰いでから**対応する |
| C | **自主的に再配置＋バイト一致検証を実施**し、恒久対策を提案する |

### ③ 却下理由

- **A却下**：表示遅延か配置失敗かを**区別する手段を持たないまま終業する**ことは、翌日の作業基盤を検証なしで信頼することに等しい。
- **B却下**：エスカレーション条件非該当の事象であり、**判断を仰ぐ間に終業時刻を超過**する。かつ「配置できているか」は**AIスライド自身が検証可能**な事項であり、統括の判断を要しない。

### ④ 採用根拠（選択肢C）

**再配置後に`diff`によるバイト一致検証を実施し、IDENTICALを確認**した。同時に恒久対策を提案した。

判断の核心は次の構造認識である：**単一書き込み者原則（第8条）のもとでは、書込結果の検証責任もAIスライドに一元化される。検証を省略すると統括側から誤りを検出できない構造になる。**

つまり**第8条を受け入れた時点で、検証は義務として付随していた**。

### ⑤ 統括判定

✅ **全面採用（8/17 EODクロージング）｜第11条候補として条文化**

**第11条案（統括発行の暫定文面）**：

> 「**AIドライブへの書込完了後は、必ずバイト一致検証（`diff`による IDENTICAL 確認）を実施する。単一書き込み者原則（第8条）のもとでは書込結果の検証責任もAIスライドに一元化されるため、検証を省略すると統括側から誤りを検出できない構造となる。**」

> 統括評価：「『書込結果の検証責任もAIスライドに一元化される』という洞察は、**第8条の必然的帰結を明文化**したもの」

## 📌 事例005｜8章8.5節｜訴求文例③の逐語転記を回避（84＝12パターン問題）

- 適用日：**2026-08-18（火）**
- 対象：Brain販売原稿 8章 8.5節
- 分類：**運用ルール第9条と第10条の衝突処理**

### ① 状況

B-6本体7章7.5節の**訴求文例③**は、Brain 8章への転用素材として指定されていた。しかしその文中に次の記述がある。

> 「**機能層**では、**7テーマ×12パターン=84組み合わせマトリクス**による最適レイアウト自動選定。」

一方、Brain 6章では**「設計12種／実装11種」の2層構造**を明記し統括承認を得ている（8/16判定①）。訴求文例③を**運用ルール第9条（原本1文字照合＝逐語転記）に従って転記すると、6章で誠実に開示した2層構造が8章で無言のうちに消え、「12パターン実装済」と読める**状態になる。

**第9条（原本を逐語で扱う）と第10条（数値の前提を落とさない）が正面から衝突した。**

### ② 検討した選択肢

| 選択肢 | 内容 |
|:---:|-----|
| A | 訴求文例③を**逐語転記**する（第9条を最優先） |
| B | 逐語転記し、**直後に「設計12／実装11」の注記を追加**する |
| C | **逐語転記せず**、3層の名称と追随難度を**本文として再構成**する |

### ③ 却下理由

- **A却下**：6章の2層構造開示と正面から矛盾する。**同一原稿内で数値の扱いが変わることは、6章の誠実さ自体を疑わせる**。第9条は「原本を正確に扱う」ためのルールであり、**原本の数値を訂正なく持ち込む口実にはならない**。
- **B却下**：8.5節は統括指定で**8〜12%（176〜288字）の分量制約**がある。注記を入れると上限を超過し、判定依頼3の趣旨（補強節を膨らませない）に反する。また補強節で数値の但し書きを始めると、**「なぜ追いつけないか」という節の主題がぼやける**。

### ④ 採用根拠（選択肢C）

8.5節では**3層の名称（機能層／体験層／戦略層）と追随難度（中／高／極高＋3〜6・6〜12・12〜24ヶ月）のみを本文化**し、**「84」「12パターン」の数値を持ち込まなかった**。

判断根拠は3点：

1. 8.5節の役割は統括判定④で「**なぜ追いつけないか**」の補強と定義済であり、**必要なのは難度と時間であって、パターン数ではない**
2. 84通りの訴求は**6章で2層構造つきで済んでおり、8章で再掲する必要がない**
3. 結果として8.5節は**244字＝10.6%**で統括レンジ内に収まった

**事例002（月ROI）と同一原理**——**訴求のために数値の前提を落とさない**——に立脚している。

### ⑤ 統括判定

✅ **承認（8/18 21:00 判定⑥｜事後承認）｜⭐ 第13条の正式追加に至った初回適用事例**

**⚠️ 併せて提示した第13条候補は8/18 21:00連結④ 判定⑥で正式追加**：「第9条は、原本の記述が後続章で開示済の前提と矛盾する場合に限り逐語転記を免除する。この場合は原本の要素を再構成して本文化し、判断根拠を第10条 適用事例集に登録する。」

## 📌 事例006｜終章9.3節｜段階値上げの根拠を「緊急性」から「受け取るものの量」へ再構成

- 適用日：**2026-08-19（水）**
- 対象：Brain販売原稿 終章 9.3節「価格について｜なぜこの値段なのか」
- 分類：**訴求技法の回避による一貫性担保**

### ① 状況

終章の唯一の素材`SALES_PLAN.md`は、段階値上げを「**ローンチ価格／希少性訴求／先着30名限定**」として設計していた。参考資料でも段階値上げは「初期購入者への価値提供＋**緊急性**」として整理されている。

これをそのまま終章に書くと「**早く買わないと損をする**」という緊急性訴求になる。しかし8章末尾で「あなたに必要なのは、判断する力でしょうか。それとも、明日提出する1枚でしょうか」と**判断を購入者に返した姿勢**と正面から衝突する。**原稿全体の一貫性が最終章で崩れる**構造を検出した。

### ② 検討した選択肢

| 選択肢 | 内容 |
|:---:|-----|
| A | 素材どおり「**先着◯名限定・ローンチ特価**」の希少性訴求として書く |
| B | 段階値上げに**言及しない**（最終価格のみ提示） |
| C | 段階の存在を書き、根拠を「**初期購入者が受け取るものが少ないから下げる**」に**再構成**する |

### ③ 却下理由

- **A却下**：緊急性訴求は購入判断を急がせる技法であり、8章で確立した「煽らずに判断材料を渡す」姿勢を終章で裏切る。**最終章での破綻は原稿全体の信頼性に及ぶ**。
- **B却下**：段階を隠すと、**後から購入した方が高い価格を払う理由が説明されない**。判断原理1「数値は下げず、隠さず、受け取られ方の問題として処理する」に反する。第1段階で購入した方も「なぜ安かったのか」を理解できない。

### ④ 採用根拠（選択肢C）

段階値上げという**設計骨格は維持**し、根拠を**自ツール内部の論理**に置き換えた。

> 「初期にお迎えする方が受け取るものは、後から購入される方より少ないからです。レビューがまだ反映されていない。追加のテンプレートもまだ増えていない。**受け取るものが少ない分、価格を下げる。** それだけです」

さらに「**段階が上がるのは、中身が増えたときだけです。時間の経過を理由に上げることはしません**」と明記し、**値上げの条件を自ら縛った**。

| # | 効果 |
|:---:|-----|
| 1 | 緊急性訴求を使わずに段階構造を説明できる |
| 2 | **出所（競合分析）への言及が構造的に不要になる**（発信ポリシー｜終章固有リスク1を回避） |
| 3 | 値上げ条件の明示により、**後続購入者への説明責任も同時に果たす** |

**判断原理1と同一原理**——段階構造を下げず隠さず、**受け取られ方の問題として処理**した。

### ⑤ 統括判定

✅ **承認（8/19 21:00 判定⑤｜事後承認）**
