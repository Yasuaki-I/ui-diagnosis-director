## 📐 露出時の運用ルール

### ルール1｜"実話"であることを担保

- **抽象化した経験談ではなく、具体的な日付・成果物・数値** を必ず含める
- 例：「7/28に builder v16 → v16.5 を実装。145行追加、後方互換完全維持、実データPPTX生成で完全一致確認」

### ルール2｜"3参考資料の位置づけコメント" は誠実に言及

- Phase A で追加した A-3 コード内コメント（3参考資料の位置づけ）は、
  「非エンジニアがAI活用時に、参考資料の位置づけをコード側にも残す」設計思想の実例として言及可
- デジタル庁PDL1.0は正確に記載

### ルール3｜"物理的干渉" を発信ネタに使わない

- v3.5コアとB-5の分離判断のような "実装上の物理干渉リスク" は、
  発信ネタとしては地味／専門的すぎるため、**note本文への露出は控える**
- 3者体制の実効性を語る一素材としては言及可

### ルール4｜Brain販売との整合

- 9月上旬のBrain販売開始までは、"実話の積み上げ" 期
- 販売告知そのものよりも、**販売物の中身に自然に接続する実話** を優先
