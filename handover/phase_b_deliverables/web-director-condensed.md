## 📌 UI診断ディレクター文脈での中核原則（元スキル抽出＋再解釈）

### 原則1｜UIデザインの4基本原則（元スキル継承・診断適用視点で再解釈）

| 原則 | 元スキル定義 | UI診断ディレクターでの適用 |
|------|--------------|-------------------------|
| **視認性** | 重要な要素は目立たせる／WCAG AA基準コントラスト比4.5:1以上／階層構造を明確に | 診断項目「視覚階層」「情報の優先順位」の判定根拠。特に**バナー掲載媒体診断（v3.5コア）** で媒体特性ごとの視認性判定に直結 |
| **フィードバック** | ユーザーアクションへの即応／ローディング状態表示／成功・エラー明示 | 診断項目「インタラクション設計」の判定根拠 |
| **一貫性** | デザインパターン統一／同機能同UI／ブランドガイド遵守 | 診断項目「ブランド整合性」「デザインシステム」の判定根拠。**PPT出力の7テーマ×8色階調（Phase A A-1）** も本原則の実装 |
| **シンプルさ** | 不要要素の削除／1画面1メッセージ／認知的負荷軽減 | 診断項目「情報密度」「認知負荷」の判定根拠 |

**検証ステップ**：診断時、上記4原則のどの原則に照らして減点/加点したかを診断結果に明記できる状態を担保する。

### 原則2｜ユーザビリティの5要素（元スキル継承・診断項目マッピング）

| 5要素 | 元定義 | 10項目スコア（v3.5候補）対応 |
|-------|--------|---------------------------|
| 学習しやすさ | 初めてでも直感的 | 「初回訪問者への理解容易性」 |
| 効率性 | タスクを素早く完了 | 「主要CTA到達コスト」 |
| 記憶しやすさ | 再訪時も迷わない | 「情報構造の予測可能性」 |
| エラー防止 | ミスを防ぐ設計 | 「フォーム設計品質」 |
| 満足度 | 使っていて心地よい | 「情緒的整合性」（審美性・トーン） |

**判断基準**：診断時、10項目スコアのうち上記5要素に対応する項目は本表を参照根拠として明示する。

### 原則3｜アクセシビリティ（診断必須観点）

- キーボード操作対応
- スクリーンリーダー対応
- **色だけに頼らない情報伝達**（→ Phase A A-1の8色階調＋閾値色設計の判断根拠）
- テキストサイズ調整可能

**数値位置踏込**：WCAG AA基準（コントラスト比4.5:1以上）を診断項目の閾値として明記できる状態を担保する。

### 原則4｜モバイルUX（診断必須観点）

- **タッチターゲットサイズ：44×44px以上**（← 診断項目の絶対基準として採用可能）
- スワイプジェスチャーの活用
- 片手操作を考慮
- ページ読み込み速度の最適化

**数値位置踏込**：診断結果に「タッチターゲット44px未満：X箇所」のような具体件数表記を可能にする。

## 📐 情報アーキテクチャ（診断判断の根幹）

### サイト構造3原則（診断適用）

1. **カードソーティング**：ユーザーがどう情報を分類するかのメンタルモデル調査
   - **診断適用**：ナビゲーション設計の妥当性判定根拠
2. **階層の深さ**：3クリック以内で目的到達／パンくずリストで現在位置明示
   - **診断適用**：「情報アーキテクチャの深さ」判定根拠（3クリックルールを閾値として使用可能）
3. **ラベリング**：わかりやすい名称／専門用語回避／一貫性
   - **診断適用**：「用語の一貫性」「専門用語過多」判定根拠

**検証ステップ**：診断結果に「3クリックルール違反：X箇所」「専門用語のみで説明されている要素：X箇所」のような形で数値化できる状態を目標にする。

## 🎨 カラー・タイポグラフィ（Phase A A-1と直結）

### カラー設計（60-30-10ルール）

- **プライマリー**：ブランドの主要色（60%）
- **セカンダリー**：アクセントカラー（30%）
- **ニュートラル**：背景・テキスト（10%）
- **システムカラー**：成功(緑)／警告(黄)／エラー(赤)／情報(青)

**Phase A A-1との接続**：
- 7テーマ×8色階調は、上記4分類（プライマリー／セカンダリー／ニュートラル／システム）を **診断結果のPPT出力に自動適用** する実装
- 診断時のカラー設計評価は、60-30-10ルールを絶対基準として使用可能

### タイポグラフィ設計基準（数値位置踏込）

| 項目 | 基準値 | 診断適用 |
|------|--------|---------|
| 本文フォントサイズ | 16px以上 | 「本文可読性」判定閾値 |
| 行間 | 1.5〜1.8倍 | 「読みやすさ」判定閾値 |
| 1行の文字数（英語） | 45〜75文字 | 「行長適正性」判定閾値 |
| 1行の文字数（日本語） | 30〜40文字 | 同上 |
| 見出し階層 | h1 > h2 > h3 | 「情報階層明示性」判定根拠 |

**日本語フォント推奨**：Noto Sans JP／游ゴシック
※ 元スキル記載の「ヒラギノ角ゴ」はmacOS専用のため、PPT出力での自動採用は避ける

- シンプルなナビゲーション

**診断適用**：バナー掲載媒体診断（v3.5コア）において、掲載媒体の主要閲覧デバイスに応じた設計妥当性判定の根拠。

## ⚡ パフォーマンス最適化（診断判断の絶対基準）

### Core Web Vitals（診断必須指標）

| 指標 | 基準値 | 診断適用 |
|------|--------|---------|
| **LCP** (Largest Contentful Paint) | 2.5秒以内 | 「初期表示速度」判定閾値 |
| **FID** (First Input Delay) | 100ms以内 | 「初回インタラクション反応」判定閾値 |
| **CLS** (Cumulative Layout Shift) | 0.1以下 | 「レイアウト安定性」判定閾値 |

**検証ステップ**：診断時、上記3指標の閾値超過があれば減点根拠として明記する。

## 🚫 元スキルから明示的に **削除** した項目とその理由

| 削除項目 | 削除理由 |
|---------|---------|
| generate_sitemap.py スクリプト使用方法（20行） | UI診断ディレクターはサイトマップ生成機能を持たないため |
| Requirements Definition Template 各セクション詳細（60行） | Webサイト新規制作用テンプレであり、既存サイト診断には不要 |
| Wireframe Guidelines 詳細（30行） | 既存サイト診断では原則1〜4の基本原則で代替可能 |
| User Flow Template（20行） | 診断結果ではなく、新規設計時のみ必要 |
| クライアント提案書テンプレ全般（30行） | UI診断ディレクターは診断結果の出力が主目的で、提案書全体構成は範囲外 |

**保持した理由の逆説明**：削除した項目群は「Webサイトを **これから作る** ためのテンプレ」であり、UI診断ディレクターは「既に **存在するサイトを診断する** 」ツールであるため。
