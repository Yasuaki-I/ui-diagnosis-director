|-------------------|-------------|---------|
| `proposal_categorization` | `category` | 提案項目を並列カテゴリで整理する用途と、`category` の並列grid構造が一致 |

## 📐 12種パターン詳細（各パターン8フィールド構造）

各パターンについて、以下の8フィールドで判断基準を明文化する。

### 1｜`category`（分類）— shape: `grid`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 2〜4段のグリッドに要素を並列配置。要素間の視覚的重み付けは行わず、フラットな並列関係を強調 |
| **診断適用ケース** | `proposal_categorization`（提案項目のカテゴリ整理） |
| **使うべき条件** | 要素数が **4〜12個**／要素間に階層・順序・優先度がない／各要素の重要度が概ね等価 |
| **避けるべき条件** | 要素数が3個以下（`comparison` が適切）／要素間に明確な優先順位がある（`pyramid` が適切）／要素間に因果関係がある（`sequence` が適切） |
| **数値位置踏込** | 推奨要素数：4〜12個／グリッド段数：2〜3段／要素間余白：グリッドセル辺の10〜15%／最小フォント：本文14pt以上（1280×720キャンバス基準） |
| **検証ステップ** | 描画後、要素数が上限12を超えていないか自動チェック／要素サイズが均等（±5%以内）か確認 |
| **拡張5層接続** | 第5層｜「フラットな並列関係」の視覚原則を担う。Brain販売原稿では「10項目スコアを均等にカテゴリ化する診断ツール」の訴求根拠 |
| **B-1／B-2連携** | B-1「情報アーキテクチャ」章の「カードソーティング」原則と論理整合／B-2デジタル庁ガイドブック想定領域（4-15ページ情報アーキテクチャ）と参照レイヤー2で整合性チェック対象 |

### 2｜`pyramid`（ピラミッド）— shape: `triangle`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 三角形の階層構造。上位が少数・下位が多数となる ピラミッド型。優先度・重要度・階層関係を上下軸で表現 |
| **診断適用ケース** | `priority_ranking`（優先順位表示） |
| **使うべき条件** | 明確な上下階層／優先順位を持つ／**3〜5段** の階層／上位ほど重要（または少数）である関係が成立 |
| **避けるべき条件** | 階層数が2段のみ（`comparison` が適切）／階層数が6段以上（視覚認知限界超過／`breakdown` の tree に切替）／階層間に反復関係がある（`cycle` が適切） |
| **数値位置踏込** | 推奨階層数：3〜5段／各段の高さ比率：黄金比またはフィボナッチ比推奨／最上段幅：最下段幅の20〜30%／最小フォント：14pt以上 |
| **検証ステップ** | 階層数が3〜5段の範囲内かチェック／上位ほど幅が狭くなっているか（幅減少率の単調性）を検証 |
| **拡張5層接続** | 第5層｜「上下階層」の視覚原則を担う。診断結果の10項目スコア上位3項目を優先訴求する際に発火 |
| **B-1／B-2連携** | B-1「原則1｜視認性（階層構造を明確に）」と直結／B-2想定領域（4-15ページ）情報アーキテクチャ原則との整合性チェック |

### 3｜`comparison`（比較）— shape: `side_by_side`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 2〜3要素を左右（または上下）に並列配置。各要素は同サイズ・同構造で描画し、対比を強調 |
| **診断適用ケース** | `before_after`（改善前後の対比） |
| **使うべき条件** | 比較対象が **2〜3個**／各対象の属性項目が同一構造で並ぶ／対比の主眼が「同一次元の相違」（例：Before/After、A案/B案） |
| **避けるべき条件** | 比較対象が4個以上（`category` が適切）／対比の主眼が「対照的2要素の強調」（`contrast` の split_screen が適切） |
| **数値位置踏込** | 推奨要素数：2〜3個／要素間ギャップ：キャンバス幅の3〜5%／各要素の属性項目数：5個以下推奨／最小フォント：本文14pt／見出し18pt以上 |
| **検証ステップ** | 各要素の構造が同一か（属性項目数の一致）／各要素サイズが均等（±2%以内）か検証 |
| **拡張5層接続** | 第5層｜「対称的並列」の視覚原則を担う。Before/After形式の診断結果表示で発火 |
| **B-1／B-2連携** | B-1「プロジェクトタイプ別診断視点」の各タイプ比較記述と論理整合 |

### 4｜`sequence`（順序）— shape: `arrow_chain`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | ステップを矢印で連結した左→右（または上→下）の連鎖構造。時系列・因果関係を明示 |
| **診断適用ケース** | `user_flow`（ユーザーフロー表示） |
| **使うべき条件** | ステップ数が **3〜7個**／ステップ間に明確な順序（時間・因果）／終端が明示可能（フロー完了地点） |
| **避けるべき条件** | ステップ数が2個以下（`comparison` が適切）／ステップ数が8個以上（認知負荷過大／`breakdown` で構造分解）／終端が循環する（`cycle` が適切） |
| **数値位置踏込** | 推奨ステップ数：3〜7個（Miller's Law 7±2 準拠）／矢印長：各ステップボックス幅の30〜50%／ステップボックス幅：均等（±3%以内）／最小フォント：14pt以上 |
| **検証ステップ** | ステップ数がMiller's Law範囲内か／矢印方向が一貫（すべて左→右 or 上→下）か／終端明示があるか |
| **拡張5層接続** | 第5層｜「時系列・因果」の視覚原則を担う。ユーザージャーニー診断結果で発火 |
| **B-1／B-2連携** | B-1「情報アーキテクチャ｜階層の深さ（3クリックルール）」と論理整合（ステップ数の閾値設定根拠） |

### 5｜`cycle`（循環）— shape: `circle_arrow`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 円環上に配置された要素群を矢印で連結。反復プロセス・継続改善サイクルを表現 |
| **診断適用ケース** | `improvement_cycle`（継続改善サイクル、PDCA型） |
| **使うべき条件** | 要素数が **3〜6個**／プロセスが循環（始点と終点が同一）／反復性が本質的な意味を持つ |
| **避けるべき条件** | 要素数が2個以下（`comparison` が適切）／要素数が7個以上（円環内認知限界超過）／プロセスが一方向のみで循環しない（`sequence` が適切） |
| **数値位置踏込** | 推奨要素数：3〜6個／円環直径：キャンバス短辺の55〜70%／各要素配置角度：360°÷要素数（等角配置）／最小フォント：14pt |
| **検証ステップ** | 要素配置角度が等角か（±1°以内）／矢印方向が円周に沿った一方向か／始点と終点が同一位置か |
| **拡張5層接続** | 第5層｜「循環・反復」の視覚原則を担う。継続改善型の診断結果表示で発火 |
| **B-1／B-2連携** | B-1「原則2｜フィードバック」の反復ループ設計と論理整合 |

### 6｜`funnel`（絞り込み）— shape: `trapezoid`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 上部が広く下部が狭い台形の連続で構成。上から下へ向かって絞り込まれる過程を視覚化 |
| **診断適用ケース** | `conversion_funnel`（コンバージョンファネル） |
| **使うべき条件** | 段階数が **3〜6段**／各段階で数値（%・件数）が減少する／絞り込みの意味が本質的（脱落分析等） |
| **避けるべき条件** | 段階数が2段以下（`comparison` が適切）／段階数が7段以上（下段が視認不可）／数値が減少しない（`sequence` が適切） |
| **数値位置踏込** | 推奨段階数：3〜6段／各段の幅減少率：均等または段階的（20〜40%）／最下段最小幅：キャンバス短辺の10%以上（視認性担保）／最小フォント：14pt／数値表示：各段右横に絶対値＋率併記 |
| **検証ステップ** | 幅減少が単調（各段が上段より狭い）か／各段の数値表示が絶対値＋率で併記されているか |
| **拡張5層接続** | 第5層｜「絞り込み」の視覚原則を担う。EC・LP系診断のコンバージョンボトルネック表示で発火 |
| **B-1／B-2連携** | B-1「プロジェクトタイプ別診断視点｜ECサイト／ランディングページ」のCVR観点と論理整合 |

### 7｜`timeline`（時間軸）— shape: `horizontal_bar`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 水平軸上にマイルストーン・期間バーを配置。時間の流れを左→右で表現 |
| **診断適用ケース** | `schedule`（スケジュール・マイルストーン表示） |
| **使うべき条件** | 時間軸が明示的（日付・週・月・年）／マイルストーン数が **4〜10個**／各期間の長さに意味がある |
| **避けるべき条件** | 時間軸が非連続（`sequence` が適切）／マイルストーン数が11個以上（視認性低下）／期間長に意味がない（`sequence` が適切） |
| **数値位置踏込** | 推奨マイルストーン数：4〜10個／時間軸ラベル：起点・終点＋中間3〜5点／バー高さ：キャンバス高さの5〜8%／最小フォント：12pt（ラベル）／14pt（見出し） |
| **検証ステップ** | 時間軸ラベルが等間隔（時系列単位）か／マイルストーン数が上限10以内か／各バーの重なりが意図通りか |
| **拡張5層接続** | 第5層｜「時間軸」の視覚原則を担う。プロジェクトスケジュール診断・改善ロードマップ表示で発火 |
| **B-1／B-2連携** | B-1「情報アーキテクチャ」の順序原則と論理整合 |

### 8｜`breakdown`（分解）— shape: `tree`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 上位1要素から下位複数要素へと枝分かれするツリー構造。全体→構成要素の分解関係を表現 |
| **診断適用ケース** | `score_breakdown`（10項目スコアの内訳表示） |
| **使うべき条件** | 分解の階層が **2〜3層**／各層の子ノード数が **2〜7個** ／全体と部分の関係が明示可能 |
| **避けるべき条件** | 階層が1層のみ（`category` が適切）／階層が4層以上（視認限界超過／画面分割推奨）／子ノード数が8個以上（`category` へ変換） |
| **数値位置踏込** | 推奨階層：2〜3層／各層の子ノード数：2〜7個／ノード間垂直間隔：キャンバス高さの8〜12%／エッジ線太さ：1〜2pt／最小フォント：12pt |
| **検証ステップ** | 階層数が3層以内か／各層の子ノード数がMiller's Law範囲内（7±2）か／エッジ交差がないか |
| **拡張5層接続** | 第5層｜「分解・階層」の視覚原則を担う。10項目スコアの構造分解表示で発火（v3.5コアの中核出力） |
| **B-1／B-2連携** | B-1「原則1｜視認性（階層構造）」・「情報アーキテクチャ｜階層の深さ」と直結／B-2想定領域（16-27ページ／28-40ページ）と参照レイヤー2で整合性チェック対象 |

### 9｜`contrast`（対比）— shape: `split_screen`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 画面を左右または上下に2分割し、対照的な2要素を並置。境界線・背景色で対比を強調 |
| **診断適用ケース** | `ux_contrast`（UX上の対照的要素、Good/Bad UI例等） |
| **使うべき条件** | 対比対象が **正確に2個**／対比の主眼が「対照的属性の強調」（例：Good/Bad、正/誤）／視覚的インパクトが目的の一部 |
| **避けるべき条件** | 対比対象が3個以上（`comparison` の side_by_side が適切）／対比属性が同次元（`comparison` が適切）／対比の主眼が「詳細比較」（`comparison` が適切） |
| **数値位置踏込** | 対比対象：厳密に2個／画面分割比：50:50（対等比較の場合）または60:40（片方強調の場合）／境界線：2〜4pt／各領域の内側マージン：領域幅の5〜8%／最小フォント：本文14pt／見出し18pt以上 |
| **検証ステップ** | 対比対象が2個限定か／画面分割比が想定通りか／境界線コントラスト比がWCAG AA基準（4.5:1）以上か |
| **拡張5層接続** | 第5層｜「対照強調」の視覚原則を担う。Good/Bad UI診断表示で発火 |
| **B-1／B-2連携** | B-1「原則1｜視認性（コントラスト比4.5:1以上）」と直結（境界線コントラスト基準の根拠） |

### 10｜`integration`（統合）— shape: `merge`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 複数の入力要素が中央または右端の1要素に統合される合流構造。矢印またはパスで統合関係を表現 |
| **診断適用ケース** | **v3.5時点は診断マッピング対象外**（`DIAGNOSIS_TO_PATTERN` に紐付けなし）／Phase B以降の内部統合ロジック用の予約枠 |
| **使うべき条件** | 統合前要素が **2〜5個**／統合結果が1個の明確なアウトプット／統合の意味が本質的（因果・合成・帰結） |
| **避けるべき条件** | 統合結果が複数（`network` が適切）／統合前要素が6個以上（`funnel` の絞り込みが適切）／統合関係が反復（`cycle` が適切） |
| **数値位置踏込** | 統合前要素：2〜5個／統合パス角度：中央への収束角度は各要素の位置に応じて最短経路／統合結果ボックス：統合前要素の1.2〜1.5倍サイズ／最小フォント：14pt |
| **検証ステップ** | 統合パスが交差せずに収束しているか／統合結果が視覚的に強調（サイズ・色）されているか |
| **拡張5層接続** | 第5層｜「合流・統合」の視覚原則を担う。将来的に「複数診断項目の統合結果表示」用途で発火予定 |
| **B-1／B-2連携** | v3.5時点では連携なし（Phase B以降の実装時に本欄を更新） |
| **設計判断メモ** | 12種の中で唯一 `DIAGNOSIS_TO_PATTERN` に紐付いていない理由は、v3.5時点の10項目スコア・11診断カテゴリのいずれにも「複数入力の統合」構造がないため。Phase C以降で診断項目が拡張された際、本パターンを診断マッピングに追加する余地を残す |

### 11｜`framework`（フレームワーク）— shape: `quadrant`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | 直交する2軸で4象限を構成。各象限に評価対象を配置し、2軸評価による分類を可視化 |
| **診断適用ケース** | `impact_cost_matrix`（インパクト×コストの2軸評価マトリクス） |
| **使うべき条件** | 評価軸が **正確に2軸**／各軸に明確な尺度（高/低・大/小・重要/非重要等）／評価対象が **4〜16個** |
| **避けるべき条件** | 軸が1軸のみ（`pyramid` または `sequence` が適切）／軸が3軸以上（`framework` では表現不可／複数の `framework` に分割）／評価対象が17個以上（プロット過密／`network` の node_edge が適切） |
| **数値位置踏込** | 評価対象：4〜16個／各象限の面積：均等（25%±3%）／軸ラベル：軸両端に配置／プロット点直径：キャンバス短辺の1.5〜3%／最小フォント：軸ラベル14pt／プロットラベル12pt |
| **検証ステップ** | 軸が直交（90°）か／プロット点の重なりがないか／各象限の面積が均等か |
| **拡張5層接続** | 第5層｜「2軸評価」の視覚原則を担う。改善施策のインパクト×コスト評価表示で発火（Brain販売原稿の中核訴求） |
| **B-1／B-2連携** | B-1「プロジェクトタイプ別診断視点」の重点観点の2軸評価と論理整合 |

### 12｜`network`（ネットワーク）— shape: `node_edge`

| フィールド | 内容 |
|-----------|------|
| **視覚構造の要旨** | ノード（要素）とエッジ（関係線）で構成されるグラフ構造。ノード間の多対多関係を可視化 |
| **診断適用ケース** | `site_structure`（サイト構造・情報ネットワーク表示） |
| **使うべき条件** | ノード数が **6〜20個**／ノード間関係が多対多（1対多や1対1なら `breakdown` / `sequence` が適切）／関係性そのものが主眼 |
| **避けるべき条件** | ノード数が5個以下（`category` または `breakdown` が適切）／ノード数が21個以上（視認限界超過／絞り込み推奨）／関係が階層のみ（`breakdown` の tree が適切） |
| **数値位置踏込** | 推奨ノード数：6〜20個／エッジ線太さ：関係性の強度に応じて1〜3pt／ノード直径：関連度に応じてキャンバス短辺の3〜6%／最小フォント：ノードラベル12pt／レイアウト：force-directed または hierarchical 推奨 |
| **検証ステップ** | ノード数が上限20以内か／エッジ交差数が可能な限り最小化されているか／孤立ノード（エッジなし）がないか |
| **拡張5層接続** | 第5層｜「多対多関係」の視覚原則を担う。サイト構造診断・情報ネットワーク表示で発火 |
| **B-1／B-2連携** | B-1「情報アーキテクチャ｜サイト構造3原則」と直結（サイト構造診断の視覚化基盤） |

Phase A A-2 の11マッピングそれぞれについて、なぜそのパターンを選定したかの論理根拠を明示する。上表と重複する情報も、独立した参照根拠として本章に集約する。

| 9 | `ux_contrast` | `contrast` | Good/Bad対照は2分割強調が最強 | `comparison`（対照インパクトが弱まる） |

| 11 | `site_structure` | `network` | ノード間関係の多対多表現 | `breakdown`（tree構造では循環関係が表現不可） |
