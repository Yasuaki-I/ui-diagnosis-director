## 🎯 本ドキュメントの位置づけと設計判断

### なぜ「要約版」ではなく「参照ルールブック」なのか（判断基準明示）

デジタル庁「ダッシュボードデザインの実践ガイドブック」は58ページの視覚重視資料であり、以下の理由で **完全要約版アプローチを採らない** ことを Phase B 着手前に判断した：

| 判断根拠 | 詳細 |
|---------|------|
| **1. attribution_policy_20260727_rev2.md 遵守** | 3参考資料の内部仕様・実名列挙禁止ルールにより、原本内容の大量転記はリスク。B-2成果物が「原本の要約を貼るだけ」になると、UI診断ディレクター側の独自価値が消える |
| **2. 原本ライセンスの明確化** | デジタル庁資料は **PDL1.0** で公開されており、UI診断ディレクターは "PDL1.0準拠で参照する側" として明確に位置づけるべき |
| **3. B-1との構造整合** | B-1「web-director-condensed.md」は元スキル9KBの凝縮版（元素材を短くする）／ B-2の元素材はPDF 58ページ×画像ベース → 凝縮は物理的に困難 |
| **4. Brain販売原稿への接続** | 「診断における具体的な参照方法」を示す方が、要約版より訴求力が高い |

### 用途（3層）

1. **UI診断ディレクター診断ロジック側の参照根拠**：診断項目ごとに「デジタル庁ガイドブック該当箇所」への参照ルートを提示
2. **Brain販売原稿での訴求材料**：「デジタル庁公式ガイドブックをPDL1.0準拠で参照する診断ツール」というポジショニング根拠
3. **AIスライド／Claude-Chat側の運用ルールブック**：3参考資料 attribution policy の実運用ガイド

## 🧭 UI診断ディレクターにおける「参照レイヤー」設計

デジタル庁ガイドブックは、UI診断ディレクターの診断ロジックにおいて **3層の参照レイヤー** で使用する：

### 参照レイヤー1｜診断項目の権威付け（背景ルート）

**目的**：診断結果に対して「なぜその判定基準を採用したか」の権威根拠を提示する

**適用ケース**：
- ユーザーから「その判定基準の根拠は？」と問われた際、UI診断ディレクター GPTs は「デジタル庁公式ガイドブック（PDL1.0）にて公開されている原則を参照」と回答できる
- 診断結果PPT出力時、脚注/注記欄に「参考資料：デジタル庁ダッシュボードデザインの実践ガイドブック（PDL1.0）」を明示

**判断基準**：
- 直接的な用語引用・数値転記はしない（attribution_policy遵守）
- 「参照した」という事実を明示するに留める

### 参照レイヤー2｜診断ロジックの整合性チェック（内部検証ルート）

**目的**：診断ロジック本体（10項目スコア・12種図解パターン・7テーマ×8色階調）が、デジタル庁ガイドブックの原則群と論理矛盾しないことを検証する

**適用ケース**：
- Phase A A-1（7テーマ×8色階調）の色階調設計が、デジタル庁ガイドブックの色設計原則と論理整合しているかを内部レビュー時にチェック
- Phase A A-2（12種図解パターン）の各パターンが、デジタル庁ガイドブックの図表原則と齟齬がないかを内部レビュー時にチェック

**判断基準**：
- チェックは **内部作業**（UI診断ディレクターのInstructions更新／builder v17改修時のQA）に限定
- チェック結果は成果物には転記しない（原則の抽象度で保持）

### 参照レイヤー3｜Brain販売原稿での訴求根拠（表向きの参照ルート）

**目的**：Brain販売原稿にて「UI診断ディレクターの診断基準はデジタル庁公式ガイドブック準拠」の一文を訴求根拠として使用する

**適用ケース**：
- Brain販売原稿の中核章（拡張5層の第3層＝掲載媒体考慮／第4層＝PPTX出力の意味）で、根拠付けの一文として使用
- note連続実話シリーズにて、実装ネタとして間接言及可能

**判断基準**：
- 「準拠」の主張は、Phase A の実装（A-1／A-2）とガイドブック原則との論理整合性チェック（参照レイヤー2）が完了している範囲でのみ可能
- 具体的な章名・ページ番号・数値の引用は禁止（attribution_policy遵守）
- **「デジタル庁公式ガイドブック（PDL1.0）を参照した診断ツール」** という抽象表現を採用

## 🎨 デジタル庁ガイドブック × UI診断ディレクター 対応マトリクス

デジタル庁ガイドブックの58ページのうち、UI診断ディレクター診断ロジックに影響する領域を **論理的な章立て推定** で整理した（原本は目次のテキストレイヤーがないため、視覚読解時にAIスライド側で確認するリファレンスとして使用）：

| 想定領域（推定） | 想定ページ範囲 | UI診断ディレクター対応 |
|-----------------|--------------|-------------------|
| 前段：ガイドブックの位置づけ・目的 | 1-3 | 参照レイヤー1（権威付け）ルートの起点 |
| 情報アーキテクチャ・レイアウト原則 | 4-15 | 診断項目「視覚階層」「情報の優先順位」の根拠 |
| 色設計・カラーパレット原則 | 16-27 | **Phase A A-1（7テーマ×8色階調）との論理整合性チェック対象** |
| 図表・可視化パターン | 28-40 | **Phase A A-2（12種図解パターン）との論理整合性チェック対象** |
| タイポグラフィ・ラベリング | 41-46 | 診断項目「用語の一貫性」「情報階層明示性」の根拠 |
| アクセシビリティ・実装配慮 | 47-54 | 診断項目「WCAG準拠性」の根拠 |
| 後段：適用事例・付録 | 55-58 | 参考／診断項目直接対応なし |

**注記**：上記ページ範囲は **描画要素数（drawings_count）の分布と原本タイトルからの推定** に基づく（16-27ページに描画要素が集中しており色設計章の可能性、35ページはdrawings 2425個で図表可視化章の可能性）。**正確な章立ては、必要時に視覚読解で確認する運用**とし、B-2成果物の段階では推定範囲での参照ルート整備に留める。

## 📋 参照時の運用ルール（判断基準明示）

### ルール1｜内容の直接引用は禁止

- ガイドブック内の具体的な数値（例：色相角の推奨値）・用語（例：「システムカラー」の内部定義）・章名は、UI診断ディレクター成果物に **転記しない**
- 参照時は「デジタル庁ガイドブック（PDL1.0）にて示されている原則群を参照」という抽象表現に留める

**検証ステップ**：Phase B の各成果物・Brain販売原稿の全ドラフトについて、原本からの直接引用箇所がないか、AIスライド側で自己検証する

### ルール2｜PDL1.0の明示

- 発信・成果物すべての参照箇所で **「PDL1.0」を正確に記載** する
- 「デジタル庁著作物」等の曖昧な表記は避け、公式ライセンス名「Public Domain License 1.0」またはその略号「PDL1.0」を使用

**検証ステップ**：発信ドラフト完成時、`PDL1.0` の記載漏れがないか grep 検索で機械的にチェックする

### ルール3｜「準拠」主張の範囲限定

- 「デジタル庁公式ガイドブック準拠」の一文を訴求する際は、その主張の裏付けとなる **Phase A実装 × ガイドブック原則の整合性チェック（参照レイヤー2）** が完了している範囲でのみ使用
- Brain販売原稿の初稿ドラフトでは、「準拠」ではなく **「参照」** の表現に留め、整合性チェック完了後に必要に応じて「準拠」表現へ格上げ

**検証ステップ**：Brain販売原稿のレビュー時、「準拠」「基づく」等の表現が、対応する整合性チェックの根拠なしに使用されていないか3者レビューでチェックする

### ルール4｜バージョン管理

- ガイドブックの改訂版が発行された場合、AIドライブ側の原本を差し替え、B-2成果物のメタ情報テーブルの発行日・ページ数を更新する
- 改訂履歴を本ドキュメント末尾の「バージョン履歴」に追記する

**検証ステップ**：月次でデジタル庁の公式サイトを確認し、改訂の有無を追跡する

## 🚫 B-2に **含めない** 項目とその理由（設計判断の明示）

| 含めない項目 | 理由 |
|---------|---------|
| ガイドブック各章の具体的な要約 | attribution_policy_20260727_rev2.md 遵守／原本の直接転記回避 |
| ガイドブック内の具体的な数値（色相角推奨値等） | 同上／内部仕様の実名列挙禁止 |
| ガイドブック内の図表・イラストの転載 | 同上／PDL1.0でも転載時は出典明示が推奨だが、そもそも B-2の設計思想は「参照ルールブック」であり転載は不要 |
| ガイドブックの全ページを網羅する目次 | 用途対比で不要／必要時は原本を直接参照する運用 |
| UI診断ディレクターの診断ロジック本体 | B-2の範囲外（Phase A / B-1 / B-3 / B-4 側で担う） |

**含めない理由の逆説明**：B-2の設計思想は「原本を **どう使うか** のルール」であり、「原本を **どう複製するか** 」ではない。原本の内容そのものは、必要時にHub側原本（`/ui-diagnosis-director/_reference/design_system/`配下）を直接参照する運用に委ねる。
