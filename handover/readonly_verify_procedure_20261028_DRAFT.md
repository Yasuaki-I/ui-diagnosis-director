# 予備手順（案）｜AIドライブに接続できない日の冒頭照合（読み取り専用）｜運用日 2026-10-28（水）
> 🔴 **案（DRAFT）**：統括の確認前。正式手順（§6・`verify_md5.py`）の**代わりではなく予備**。使ったら必ず「代替手順で照合した」と記録する
> 背景：10/28、新環境のコンピューターで `/mnt/aidrive` が空。接続を試みると認証エラー401（「許可されていない実行環境」）で拒否された。読み取り用の窓口（ドライブの一覧・一時URLの発行）は使えた。許可がない理由は**未確認**

## 1. 使う条件
- `/mnt/aidrive` が接続されていない（`os.path.ismount('/mnt/aidrive')` が偽）ことを確かめ、20〜60秒待って2回再確認しても直らないとき
- 🔴 この状態では**書き込みはしない**（write5.py を含む）

## 2. 手順
1. manifest を一時URL経由で `/tmp/chk/` に取得し、B・md5 を実測（前日の manifest に載っている値と照合）
2. `fetch_ro_20261028.py <manifest>`：manifest の全件を、読み取り専用の窓口で一時URLを発行して `/tmp/ro/mirror/` に取得する（書込み操作は使わない。ブラウザ相当の User-Agent を付けないと一部が403になる）
3. 取得した `verify_md5.py` 自身の md5 が manifest の値と一致することを確かめる
4. `verify_md5.py` の **ROOT の1行だけ** を `/tmp/ro/mirror` に差し替えた複製で照合する（本体は変えない。差分は ROOT の1行のみであることを diff で示す）
5. 着到件数・新規ファイルは、ドライブの一覧（ファイル＋フォルダ両方を表示）から数える。find_prefix.py はドライブ上で動かす前提のため「一覧から数えた値」と明記する
6. 識別値（§4 #0）を照合結果から抜き出して報告する

## 3. 記録の書き方
- 「照合 N 件／NG 0 件（代替手順：読み取り専用の窓口で取得した複製を照合）」と書き、通常の照合と区別する
- 途中で取得失敗・NG があれば、最終値だけに置き換えず途中経過も残す（判定135）

## 4. 限界
- 取得した瞬間の内容を照合している。ドライブ上で直接測ったものではない
- 取得物はコンピューターの一時フォルダにあり、環境が変わると消える
