## ■ 3. 🔴 本日の検出｜バックログ案Cの前提相違

### 🔴 検出内容

⭐ **バックログ §3 案C：**

> ⭐ **「`add_text` の `height_px` 算出時に下部パディングを 6px 確保する共通化」**

🔴 **原本 `03_pptx_builder_v17_20_20260825.py` L5308〜5310（実測）：**

```
if desc and cur + 20 <= cy + card_h - 6:
    add_text(slide, cx + pad, cur, card_w - pad * 2, desc, 14,
             color=txt_color, height_px=cy + card_h - cur - 6)
```

🔴 **`- 6` が下部余白6pxの確保そのものである。⭐ 案Cの前提は既に満たされていた。**

### 🔴 真の原因｜枠高の不足

| 項目 | 値 |
|---|---:|
| ⭐ **説明文ボックスの高さ**（`card_h=104`・score有り） | 🔴 **39px** |
| ⭐ **14pt × 2行の必要高**（pt→px 1.333／行間1.2相当） | 🔴 **44.8px** |
| 🔴 **不足** | 🔴 **5.8px** |

⚠️ **`add_text` は `auto_size = MSO_AUTO_SIZE.NONE` かつ `word_wrap = True`。** 🔴 **枠高が足りなくてもテキストは枠外へ描画され続ける（切れない・エラーにならない）。**

⭐ **この2点の組み合わせが「⭐ 枠は守られているのに、⚠️ 見た目は下辺に貼りつく」現象の構造的原因である。**

### ⭐ 8/26 実測値の単位を確定

⚠️ **8/26 の「3px」は画像座標（1024×576）の値であった。** ⭐ **本日スケールを実測（x=0.8000 / y=0.8000）した。**

| 項目 | ⭐ 画像座標 | ⭐ 実座標換算 |
|---|:---:|:---:|
| カード外形 | y 219〜300（h=81） | ⭐ **y 273.8〜375.0（h=101.2）** |
| ⭐ **下辺までの余白** | ⚠️ **3px** | ⭐ **3.8px** |

⭐ **実座標3.8pxがボックス基準6pxを下回るのは、⚠️ 2行目が枠を5.8px超えて描画されているためであり、⭐ 機械算出と実測が整合した。**

⚠️ **バックログの「3px」は誤りではなく単位注記の欠落である。** ⭐ **遡及改変はせず、本設計書で単位を明示して上書き記録した（判断原理10）。**
