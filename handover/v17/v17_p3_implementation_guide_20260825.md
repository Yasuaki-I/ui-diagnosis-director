## ■ 6. 各パターンのデータ仕様

### 6-1｜`funnel`（絞り込み）｜3〜6段

```python
{'title': str,
 'stages': [{'label': str, 'score': int|None, 'description': str}, ...]}
```

⭐ **index0 が最上段（最も広い）。** ⭐ **幅比 0.90 → 0.40 で絞り込みを表現。**

### 6-2｜`cycle`（循環）｜3〜6段

```python
{'title': str,
 'cycle_name': str,                    # 円環中心の名称（任意）
 'phases': [{'label': str, 'score': int|None, 'description': str}, ...]}
```

⭐ **12時起点・時計回り固定。** ⭐ **色は4色循環（段階減衰させない）。**

⚠️ **`BLOCK_ARC` は使わない。** ⭐ **角丸矩形の円周配置＋`RIGHT_ARROW` で構成する**（8/25 実測にもとづく設計判断｜下記7章）。

### 6-3｜`contrast`（対比）｜⚠️ 2固定

```python
{'title': str,
 'sides': [{'label': str, 'score': int|None, 'items': [str]}, ...]}   # ⚠️ 必ず2件
```

⚠️ **`description` ではなく `items`（最大5件の箇条）。** ⭐ **中間色を排し2極化（薄→濃）。**

### 6-4｜`timeline`（時間軸）｜3〜7｜⚠️ requires_axes=True

```python
{'title': str,
 'axis_label': str,                            # ⚠️ 必須
 'milestones': [{'label': str, 'axis': str,    # ⚠️ axis も各件必須
                 'score': int|None, 'description': str}, ...]}
```

⚠️ **`axis_label` または各 `axis` が欠落すると `category` へフォールバックする**（統括厳守事項｜8/13）。⭐ **カードは軸に対し交互配置（決定論的）。**

### 6-5｜`network`（ネットワーク）｜3〜7ノード

```python
{'title': str,
 'nodes': [{'id': str, 'label': str, 'score': int|None}, ...],
 'edges': [{'from': str, 'to': str}, ...]}
```

⭐ **フォールバック3起動条件**（統括指示｜8/12議題4）：

| # | 条件 |
|:---:|---|
| 1 | ノード数が3〜7の範囲外 |
| 2 | ⚠️ **エッジが存在しないノードIDを参照** |
| 3 | ⚠️ **エッジが1本もない**（`node_edge` の本質を満たさない） |

⭐ **深度は入次数0をルート（深度0）として決定論的に算出。** ⚠️ **力学配置は採らない**（再現性担保｜原則③）。

## ■ 7. 🔴 `cycle` の設計変更｜⭐ 8/25 実測にもとづく

### ⚠️ 実装記録（8/14 判断④）の前提誤り

⚠️ **実装記録は「`MSO_SHAPE.BLOCK_ARC` ＋ rotation」を採るとし、「adjustments が期待通り機能しない環境が想定される」とリスク記述していた。**

⭐ **8/25 に実機同等環境で実測した結果：**

| 項目 | 実装記録の前提 | ⭐ 実測結果 |
|---|---|---|
| adjustments の単位 | ⚠️ 不明（0.0〜1.0 の比率と推定） | ⭐ **`adj0`＝開始角（**度**）／`adj1`＝終了角（**度**）／`adj2`＝環の太さ比** |

⭐ **環境依存ではなく、単位の誤認だった。**

| 案 | 構成 | 円環表現 | ⚠️ 制約 |

⚠️ **案A・Bでは、他10パターンが持つ「ラベル＋スコア＋説明」の情報構造を格納できず、`cycle` だけが図形のみのスライドになる。**
