## 1. 🚨 自己申告：NG-B「9字」の実装が是正にならなかった

### 1-1. 事実

第2便の承認に従い `_truncate_full(name, 10)` → `_truncate_full(name, 9)` に変更し、
PPTXを再生成して `verify_render.py` で実測した結果：

```
🚨 NG   slide2.xml   y=200  枠180px  14pt B  実描画186.7px  2行  ファーストビュー訴…
NG 1 件 → 要是正
```

**NGが解消していない。** 実描画幅は変更前と 186.7px のまま1pxも変わらなかった。

### 1-2. 原因：`_truncate_full(s, max_w)` の引数仕様の誤読

```python
def _truncate_full(s, max_w):
    """文字列を全角換算 max_w で切り、超えたら末尾を '…' に置換。"""
    total = 0.0
    for idx, ch in enumerate(s):
        total += 0.5 if ord(ch) < 128 else 1.0
        if total > max_w:
            return s[:idx].rstrip() + '…'   # ← 省略記号は「加算」される
    return s
```

`max_w` は **「切詰後に残す本文の全角換算幅」** であり、
超過時に付く省略記号 `…`（全角1字＝18.67px）は **max_w に含まれず加算される**。

| 引数 | 実際の表示 | 表示字数 | 実描画幅 | 枠180px |
|:---:|---|:---:|---:|:---:|
| `10`（変更前） | `ファーストビュー訴…` | 10字 | 186.7px | 🚨 超過 |
| **`9`（第1便で当方が「9字」と報告・承認された値）** | `ファーストビュー訴…` | **10字** | **186.7px** | 🚨 **超過** |
| `8` | `ファーストビュー…` | 9字 | 168.0px | ⭕ 収容 |

`max_w=9` では本文9字で打切り→`…`加算→**表示10字**となり、`max_w=10` と結果が同一になる。

### 1-3. 当方の誤りの所在

第1便の諮問で「**9字なら全10項目が余裕6px以上（最大168.0px）**」と報告したが、
この実測値 168.0px は **「表示9字」＝`max_w=8`** の測定値であった。
それを実装引数の「9」と取り違えて報告した。**統括判定の規準（表示9字・最大168.0px）自体は正しく、実装引数の対応付けを誤った。**

統括判定書の記載「切詰10→9字」は**表示字数**として解釈すれば正であり、
その場合の正しい実装引数は **`_truncate_full(name, 8)`** である。
