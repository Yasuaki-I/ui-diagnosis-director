## ■ 3. 【判定51】提供形態の推し（統括の推しを更新）＝「**Agent Skills 形式の1フォルダ**」を主軸 <!-- 協議案（第5便で協議案に切り替え） -->
### 51-1. 考え方
- **AIスライドの見解（①自分の対話AIに組み立てる）を支持し、統括の第1案（ローカル Python＋ランチャー主軸）は降格**する。AIスライドの指摘（「②は技術に慣れていない方ほど最初の一歩で離れる」「診断と生成が分断される」「総評17字を自動でやり直せない」）は正しい。
- そのうえで、①の「組み立て方」を**オープン標準（Agent Skills）の1フォルダに統一**する。中身は同じ1つのフォルダで、購入者の使う AI に合わせて**入れ方だけ**が変わる。
  - 「共有」機能は要らない（購入者が自分のアカウントで入れる）→ **判定44 の「一般公開不可」の制約を受けない**。

### 51-2. 配布物の形（案）
```
ui-diagnosis-director/          ← Brain で配布する1フォルダ（zip）
  SKILL.md                      ← 診断の手順（ヒアリング→確認A→観点提示→承認→確認B→生成）＝購入者版プロンプト
  scripts/03_pptx_builder.py    ← 採用版 builder（v17.2.17 と同一を原則）
  references/                   ← 採点基準（G項）・図解パターン仕様・書式規定など
  assets/                       ← JSON 雛形など
  README（導入手順・スクショ付き1枚）
```

### 51-3. 入れ方（購入者の AI ごと）
| 購入者の環境 | 入れ方 | 確度 |
|---|---|---|
| **Claude（Free〜）** | Customize > Skills で zip をアップロード＋「Code execution and file creation」をオン | 🟢 公式記述あり（事実1・2）。**実機は未検証** |
| **Codex（CLI／IDE）・ChatGPT デスクトップ** | フォルダを所定の場所に**置くだけ**（＝入江さんの理想に最も近い） | 🟢 公式記述あり（事実5）。**実機は未検証** |
| **Claude Code** | claude.ai で入れれば同期（事実3）。直接置く場所は**要確認** | 🟡 |
| **ChatGPT（Web・プロジェクト）** | 指示欄に SKILL.md の内容を貼る＋builder を **Project Sources** に入れる | 🟡 不具合報告あり（事実7）。**要検証** |
| 上記が使えない方 | 予備：ローカル Python＋ランチャー（判定47-B） | 🟡 Mac のメイリオ等が要確認 |

### 51-4. この形の利点と、正直な弱点
- 利点：①**ChatGPT 依存から脱する**（Claude・Codex でも同じ中身）②**lite の 8,000 字制限から解放**され、PLAIN 相当の手順を `SKILL.md`＋`references/` に分けて入れられる（＝**機能の網羅**に効く）③オープン標準なので、今後増える対応 AI にもそのまま載る。
- 弱点：①**どの環境でも「動くはず」であり、まだ1回も動かしていない**（判定53 で検証）②URL の読み取り（診断の入口・E1）の能力が AI ごとに違う③購入者の利用枠（無料プランの回数制限）で途中停止しうる④ファイル生成は各社とも「保証」ではない。
- 🔴 **販売ページには、実機で検証できた環境だけを書く**（未検証の AI を「対応」と書かない）。

## ■ 3. AIスライドに見解を求める点（10問）
各問に「賛成／条件付き賛成／反対」と、その理由をお願いします。分からない点は「未確認」と書き、推測で埋めないこと。

### B. 技術（実装担当としての見立て）
- **Q4**　**builder の読み込み**：`/mnt/data` の固定パスをやめて、スキルフォルダ内の `scripts/` から読む書き方にした場合、R-7 対策の2行方式（`exec(..., _ns)`＋`globals().update(...)`）はそのまま使えるか。環境ごとに置き場所が違うことへの対処として、より安全な書き方はあるか。
- **Q5**　**動作環境の前提**：builder は python-pptx を使う。Claude などの実行環境で python-pptx が最初から使えるか、追加で導入が要るか（ネットワークが切られた環境では導入できない可能性がある）。**統括は確認できていない**。AIスライドの把握している範囲と、V1・V2 で確かめる方法を求める。
- **Q6**　**フォント**：PPTX はメイリオ指定で、表示は購入者の PC に依存する。Mac にはメイリオが入っていない可能性がある。販売品質として、対処が必要か（代替フォントの指定・購入者への注意書きなど）。
- **Q7**　**機能の網羅**：lite の 8,000字の制限がなくなる。PLAIN 相当の手順を `SKILL.md` と `references/` に分けたとき、
  - 今の GPT の流れ（ヒアリング2問・確認A/B・承認後に生成・総評17字の自動やり直し・図解パターン）が、Claude 等でも同じように守られる見込みか
  - 長くすると、かえって守られにくくなる心配はないか
  - `SKILL.md` に入れるもの・`references/` に回すものの切り分け案

### C. 商品と区分
- **Q8**　**区分**：配布物は購入者の手元にファイルとして残る。GPT のリンクで渡していたときより、コピー・再配布がされやすくなる。公開ルール（判定31）の「購入者限定・再配布禁止」を守るうえで、追加の対策は要るか（ファイル内の表記・利用規約の文言など）。

### D. 検証
- **Q10**　V1〜V5 の検証計画（第4便 §5）は妥当か。とくに次の3点。
