# 実診断サンプル 匿名化ガイドライン

**作成日**: 2026-07-16（木）
**目的**: 実在サイトを診断した結果を「実診断サンプル」として販売資産化する際の匿名化ルールを明文化
**適用対象**: v5.2_ready 以降、Brain販売ページ・note記事・X告知等で実診断結果を公開する場合

---

## 🎯 このガイドラインの位置づけ

### なぜ必要か

Claude-Chat 統括判断（2026-07-14）で確定した「選択肢C：4事例構成（フォーマット見本3種＋実診断サンプル1件）」の運用ルールとして、実診断サンプルの匿名化ルールを事前に握っておく。後追いで匿名化する際の「モザイクなのか差し替えなのか」等の判断ブレを防ぐ。

### 適用シーン

- Brain販売ページ §7「フォーマット見本と実診断サンプル」の実診断1件
- v6以降で追加する追加実診断事例（フォロワー増加後の実案件事例等）
- X告知でシェアする実診断スクリーンショット
- note記事内で紹介する実診断事例

## 📋 匿名化 3段階ルール

### レベル1: 社名・ロゴの完全除去

**必須**: 実サイト運営者を特定できる要素を全て除去する。

| 要素 | 対応 |
|---|---|
| **社名（テキスト）** | スクリーンショット内の社名表記を全て削除（画像編集で塗り潰し） |
| **ロゴ画像** | モザイク処理ではなく **差し替え or トリミング** で完全除去 |
| **URL** | ブラウザURLバー・footer等に表示されるURLは全て削除 |
| **サービス名** | 診断対象のサービス名も伏せる（診断結果内の`service_name`フィールドも匿名表記に変更） |

**なぜモザイクではなくトリミング/差し替えなのか**：
- モザイクは「元情報の輪郭」が残るため、特定リスクが完全にはゼロにならない
- 販売ページの品質観点でも、モザイク処理は「隠している感」が出て信頼性を損なう
- トリミングまたは差し替えなら、そもそも情報が存在しないので完全なる匿名化が実現

### レベル2: 業種・企業属性の1段抽象化

**必須**: 業種名・地域名・企業規模等を1段抽象化して記載する。

| Before（具体） | After（1段抽象化） |
|---|---|
| 「大手AI企業のコーポサイト」 | 「グローバルAI企業のコーポレートサイト」 |
| 「日本の大手ECサイト」 | 「アジア圏の大手ECサイト」 |
| 「東京都心の高級レストラン」 | 「都心の高級レストラン」 |
| 「フォロワー10万人のインフルエンサーLP」 | 「10万人規模のインフルエンサーLP」 |

**なぜ1段抽象化が必要か**：
- 「大手AI企業」だけだと、生成AI業界のプレイヤー数が限られるため推測可能性が残る
- 「グローバルAI企業」に抽象化することで、地域範囲を拡張し推測を困難にする
- ただし過度な抽象化（例：「ある企業のサイト」）は情報価値がなくなるため、**1段抽象化に留める**のがバランス

### レベル3: 診断内容そのものは公開可

**方針**: スコア・強み・課題・改善提案の内容は、そのまま公開可能。

**理由**：
- 診断ノウハウそのものは入江さんの知的資産であり、公開しても問題ない
- むしろ「診断精度・視点の鋭さ」を訴求する材料になる
- 診断結果の数値（スコア41/50等）に固有名詞が含まれていない限り、追跡不能

**例外**：
- 診断コメント内に固有名詞（他社サービス名、特定人物名）が含まれる場合は、その部分だけ抽象化
- 例：「Chatwork連携機能がある」 → 「業界標準ツール連携機能がある」

## 🖼️ スクリーンショット処理の実務ルール

### 元スクリーンショットの取得

診断時にGPTsに渡したスクショ、または診断後にサイトから改めて取得したスクショを使用。

### 加工手順（推奨ツール：Photoshop / Figma / Canva等）

1. **ロゴ・社名の除去**：
   - ロゴ位置を白背景で塗り潰し、または左右トリミングで除外
   - サイト内テキストで社名が現れる箇所も同様

2. **URLバーの処理**：
   - ブラウザ画面全体を含める場合はURLバー部分をトリミング
   - サイトのfooter記載のURLも塗り潰し

3. **バッジオーバーレイの追加**（Claude-Chat補強③）：
   - 画像左上に「REAL DIAGNOSIS」バッジを追加
   - 背景色：オレンジ #F97316、文字：白、サイズ：短辺の12%程度

4. **保存形式**：
   - PNG推奨（テキストがシャープに残る）
   - ファイル名：`real_diagnosis_[分類]_[番号].png`（例：`real_diagnosis_global_ai_01.png`）

## 📝 販売ページ上での表記例

### ✅ 推奨表記

```
▼ 実診断サンプル
実在するグローバルAI企業のコーポレートサイトを診断した結果です。
プライバシー保護のため社名は伏せていますが、診断精度そのものは
本商品購入後にご自身のサイトで体験できるレベルです。
```

### ❌ 避けるべき表記

```
▼ 実診断サンプル
OpenAIのコーポサイトを診断した結果です（社名伏せ）。
```
→ 「（社名伏せ）」と書きつつ社名を出しているため、匿名化の意味がない

```
▼ 実診断サンプル
大手企業のサイトを診断した結果です。
```
→ 抽象化が過度で、業種すら伝わらず情報価値ゼロ

## 🔍 レビュー時のセルフチェックリスト

実診断サンプルを公開する前に、以下を確認：

- [ ] スクショ内に社名・サービス名が一切残っていない
- [ ] ロゴがモザイクではなく完全除去（差し替え or トリミング）されている
- [ ] URLが表示されていない（ブラウザバー・footer等含む）
- [ ] 業種・企業属性が1段抽象化されている
- [ ] 診断コメント内に他社サービス名・特定人物名が残っていない
- [ ] 「REAL DIAGNOSIS」バッジがオーバーレイされている
- [ ] 販売ページの説明文で「実在」「匿名化」の両方が明示されている

## 🚨 リスクケース：それでも特定される可能性への対応

**シナリオ**：完全匿名化しても、UIの特徴的な要素（独自の配色、フォント、レイアウト等）から特定される可能性がゼロではない。

**対応方針**：
1. **特定されても法的問題は発生しない設計**：
   - 診断内容は「公開情報からの分析」であり、営業妨害や誹謗中傷にはあたらない
   - スコア・改善提案は建設的なもので、対象サイトの信用毀損には該当しない

2. **特定された場合の対応**：
   - 対象企業から問い合わせがあった場合、誠実に「診断技術のサンプルとして使用させていただいた」旨を説明
   - 差し替え要求があった場合は速やかに応じる（別の実診断事例に置換）

3. **予防策**：
   - v6以降で実診断事例を追加する場合、可能であれば対象企業への事前連絡を検討
   - 特に「診断結果を公開してもよいか」の許諾を得られた事例を優先的に採用
