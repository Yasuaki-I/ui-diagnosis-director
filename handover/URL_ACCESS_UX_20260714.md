## 📢 本方針書の目的

7/13夜、入江さんからの重要な戦略共有：

> GPTs「UI診断ディレクター」の対話設計方針:
> ①失敗時アナウンスは丁寧かつ詳細に説明する。
> ②レポート出力は一方的な3種提示で完結させず、対話形式で1つずつ提示・選択・深掘りが可能な形式を併用する。

これはパートナー化方針の**階層1（UX品質の底上げ）**に該当し、βテスト（7/19〜）前に発売版として組み込む必要がある。

本方針書は、以下2点を統合して定義する：
1. **URLアクセス失敗時のUXフロー**（クローラー拒否時のスクショ誘導）
2. **無機質さ解消の統合設計**（Instructions文言調整による対応）

## 🔍 現状課題

### 課題1：URLアクセス失敗時の応答が不親切
現状のInstructions（`gpts-package/01_Instructions_WebDiagnosis.md`）line 20：
```
URL取得失敗時：「URLが取得できませんでした。スクリーンショットをお送りください」と1度だけ依頼
```

これは機能的には正しいが：
- **なぜ取得できなかったのか**の説明がない（クローラー拒否・404・タイムアウト等の区別なし）
- **スクショの取り方**の具体的案内がない
- **他の対処法**（別URL、期間を置いて再試行等）の提案がない
- **謝罪も配慮の言葉もない**ため無機質

### 課題2：診断プロセスがブラックボックス
GPTs実運用スクショ（scr_01〜04）を見ると：
- 「診断が完了しました」の直後に即PPTX 3ファイルが並ぶ
- **PPTXの中身がチャット側に反映されていない**
- ユーザーはPPTXを開くまで、何が分析されたか分からない

これは入江さんの指摘「PPTXの診断内容がチャットに反映されず、単なるファイル受け渡しになっている」の根本原因。

### 課題3：レポート受領後の対話動線が明示されていない
現状のInstructionsには「診断後にユーザーが質問できる」動線の明示なし。ユーザーは「診断は終わった」と認識してチャットを閉じる可能性が高く、**パートナー化階層2（対話体験の設計）が機能しない**。

## 🎯 改善方針

### 方針A：URLアクセス失敗時の丁寧なガイドフロー

#### 改善後の応答テンプレート

**Case 1: クローラー拒否（robots.txt等）の場合**
```
恐れ入ります。{URL} にアクセスを試みましたが、
このサイトはクローラー（自動アクセス）を制限しているようです。

そこで、以下いずれかの方法で診断を進められます：

【方法1・推奨】スクリーンショットをお送りいただく
以下の要領でスクリーンショットを撮影し、この画面に添付してください。
・PCの場合：Chromeで対象ページを開き、Ctrl+Shift+I → Ctrl+Shift+M（デバイスモード）→
　「Capture full size screenshot」で全体をキャプチャ
・スマホの場合：iPhoneはスクロールキャプチャ、AndroidはChromeの「共有→スクリーンショット」

【方法2】別ページを診断する
同じサイトの別ページ（トップページ、商品詳細ページ等）で
クローラーアクセスが可能な場合、そちらのURLをお送りください。

【方法3】時間を置いて再試行
一時的なアクセス制限の場合もあります。数分後に再度お試しいただけますか。

どの方法で進めましょうか？
```

**Case 2: 404 / ページが存在しない場合**
```
恐れ入ります。{URL} にアクセスしましたが、ページが見つかりませんでした。

ご確認いただきたい点：
・URLに誤字はありませんか？（似た文字列 O/0, l/1 等）
・ページが移動・削除されている可能性はありませんか？
・末尾のスラッシュ有無で違いがある可能性があります

正しいURLをお送りいただくか、
別ページを診断対象としていただけますでしょうか。
```

**Case 3: タイムアウト / 一時的なエラー**
```
恐れ入ります。{URL} にアクセスを試みましたが、
接続がタイムアウトしました。

以下のいずれかで進められます：
・数分後に再度お送りいただく
・別ページのURLで進める
・スクリーンショットを添付いただく

いかがしましょうか？
```

**Case 4: 認証必須ページ（ログイン画面）**
```
恐れ入ります。{URL} は認証が必要なページのようです。

会員限定ページや管理画面の場合、URLだけでは診断できません。
ログイン後の画面をスクリーンショットで撮影して添付いただければ、
その内容で診断できます（β機能）。

スクリーンショットをお送りいただけますか？
```

### 方針B：診断プロセスの可視化（無機質さ解消）

#### 診断中の進捗表示テンプレート

**現状**：診断中は何も表示されず、突然「診断が完了しました」となる
**改善後**：診断プロセスの各段階で短いテキストを提示

```
{URL}のUI診断を始めます。

▼ 診断中...
・ページ構造とファーストビューを確認
・10項目のスコアリング実施中
・改善提案の優先度を分析中
・PPTX3ファイルを生成中

（通常3〜5分程度）
```

※GPTsの実装制約上、リアルタイムのプログレス表示は難しいため、**診断開始時に上記のフローを1回だけ提示**する形式で実装。

#### 診断完了時のレポート提示テンプレート

**現状**：PPTX 3ファイルが並ぶだけ
**改善後**：各ファイルの内容を1〜2行で要約提示

```
{サービス名}のUI診断が完了しました。
総合スコア {XX}/50・ランク {S/A/B/C/D} と評価しました。

**① UI診断スコアカード**
📊 [ダウンロード：01_UI_Scorecard_{service_name}.pptx]
10項目のスコアとランクを1枚に集約。経営層への報告用に。

**② 改善提案リスト**
📊 [ダウンロード：02_Proposals_{service_name}.pptx]
優先度Top1は「{最優先課題の要約}」。5件の改善案を優先度順に。

**③ ビジュアル診断ボード**
📊 [ダウンロード：03_Visual_Board_{service_name}.pptx]
構造マップ・Before/After・ユーザー行動フローを視覚化。プレゼン用に。

---

**続けて、以下のような相談も可能です：**
・「Top3の改善提案について、もう少し深掘りしたい」
・「なぜこの項目のスコアが低いのか、根拠を聞きたい」
・「特定の項目（例：CTA設計）に絞って再診断したい」
・「別のページ（例：商品一覧、商品詳細）も診断したい」

気になる項目があれば、お気軽にお声がけください。
```

### 方針C：対話継続動線の明示（パートナー化階層2の簡易版）

診断完了時のテンプレート末尾に「続けて、以下のような相談も可能です」ブロックを追加することで：
- ユーザーが「まだ対話できる」ことを認識
- 具体例を4種提示することで、次の一歩を踏み出しやすくする
- v5.2_public §9の「診断結果について、そのまま質問できます」との整合を担保

## 🎯 Instructions側の実装箇所

`gpts-package/01_Instructions_WebDiagnosis.md` に以下を追加/更新：

### 更新1：セクションC「入力受付」の失敗時対応強化

**現状（line 20）**：
```
- URL取得失敗時：「URLが取得できませんでした。スクリーンショットをお送りください」と1度だけ依頼
```

**変更後**：
```markdown
- URL取得失敗時：エラー種別を判定し、以下のいずれかのテンプレートで応答する
  - クローラー拒否（robots.txt等）→ 4方法の選択肢を提示（スクショ推奨、別ページ、時間を置く）
  - 404 → URL誤字確認と別ページ提案
  - タイムアウト → 再試行 or スクショ提案
  - 認証必須 → ログイン後スクショの案内
  - 詳細な応答テンプレートは、末尾セクション「M. エラー応答テンプレート」を参照
```

### 更新2：新規セクション「M. エラー応答テンプレート」を追加
上記「方針A」の4テンプレートをそのまま格納。

### 更新3：セクションKの応答形式を「方針B」の完了テンプレートに更新
現状のline 199〜210を、方針B「診断完了時のレポート提示テンプレート」で差し替え。

### 更新4：新規セクション「N. 診断後の対話モード」を追加
```markdown
## N. 診断後の対話モード（パートナー化の核）

診断完了後、ユーザーから追加質問があった場合、以下の対応方針で応じる：

- **スコア根拠の説明**：診断ロジック（visual_data の scores 配列の comment）を参照し、
  具体的にどのUI要素が評価に影響したかを説明する
- **改善提案の深掘り**：改善提案5件のうち特定項目について、
  実装難易度・期待効果・優先順位の根拠を具体化する
- **項目単位の再診断**：特定10項目のみに絞った再診断リクエストに応じる
  （例：「CTA設計だけ詳しく」）
- **別ページの追加診断**：新しいURLまたはスクショで、上記フロー（C〜K）を再実行

**重要**：診断結果を渡して終わりではなく、ユーザーがWeb改善の次の一手を判断できるまで、
対話を通じて伴走する姿勢を保つ。「単なるツール」ではなく「業務パートナー」として応答する。
```
